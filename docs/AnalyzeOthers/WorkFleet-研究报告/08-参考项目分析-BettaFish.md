## 2. 技术架构穿透

### 2.1 Agent 编队【已确认】
- **Query Agent（资讯检索）**：新闻/社媒检索；
- **Media Agent（多模态）**：图像理解 + 情感识别 + ASR + OCR；
- **Insight Agent（数据洞察）**：面向私有数据库的查询分析（SQL 生成经 SQLAlchemy async 引擎，只读权限）；
- **Report Agent（报告生成）**：产出结构化报告；
- **ForumEngine（论坛引擎/辩论主持人）**：不属于执行者，而是**协作机制的主持者**。

### 2.2 ForumEngine 论坛协作机制（总控模式的直接参考）【已确认】
执行逻辑（README 自述）：
1. 各 Agent 在论坛中发言（把中间产出/日志发到论坛）；
2. ForumEngine **监控 agent 的日志与发言**；
3. LLM 主持人综合各方意见，**生成指导性意见**（调整研究方向、指出分歧）；
4. Agent 通过 **`utils/forum_reader.py`**（Agent 间论坛通信工具）阅读论坛，据此调整下一步；
5. **多轮循环**直到收敛（或达到轮次上限）。

→ 把角色替换即得总控模式：「总控 = ForumEngine 主持人；输入端 agent = Query/Media/Insight；输出 = Report + IM 推送」。用户的"职业经理人组织会议→明确需求→统一意见→分配任务"与该机制同构。

### 2.3 技术栈【已确认】
- **Web 后端**：Flask（`app.py` 主入口，含任务管理；`cancel_task` 等任务级 API）；
- **流式**：SSE（`flask_interface.py` 管理任务排队与流式事件推送）；
- **数据**：SQLAlchemy（async engine，洞察只读）；MindSpider 子系统（爬虫，MediaCrawler 作为 submodule，MySQL `mindspider_tables.sql` + `models_bigdata.py`）；
- **单 Agent 模式**：Streamlit 快速应用（每个 Agent 一个可独立运行的 Streamlit 页面）；
- **报告引擎**：**文档 IR（中间表示）**流水线——模板选择 → 文档排版 → **字数预算** → 逐章生成 → IR 拼接 → HTML 渲染；每块（block）过质量检查；支持 HTML/PDF/MD 三输出（WeasyPrint）；图表转 SVG；
- **配置**：Pydantic Settings + `.env.example`；
- **ML**：SentimentAnalysisModel（BERT/GPT-2/Qwen3 LoRA 微调 + 传统 ML 双轨）；
- **部署**：Docker Compose 多服务；`regenerate_latest_*` 系列脚本支持"用最新章节重装订"增量渲染；
- **测试**：pytest（ForumEngine 监控、报告引擎安全性等）。

### 2.4 工程亮点（可移植模式）
1. **字数预算（word budget）**：报告按章节分配字数配额，防 LLM 跑飞——总控"归纳"环节的输出控制手段；
2. **IR 化报告**：内容与渲染分离（IR → HTML/PDF/MD），IM 卡片渲染可复用此思想（IR → 微信/飞书卡片）；
3. **论坛即通信总线**：agent 间解耦通信（非直连 RPC），天然支持多对多发言与审计留痕。

## 4. 苏格拉底追问与钢人论证

**Q：一个舆情分析工具对 ACP 路由工具的参考价值在哪？**
不在领域，而在**协作机制**：ForumEngine 的"监控发言→主持人综合→指导→多轮"正是总控模式示例 2（"各输入端每次输入后，都必须经过总控把关、归纳、回复"）的开源实现样本。且其论坛总线设计（发言即留痕、可审计）优于点对点转发的可观测性【已确认机制存在】。

**Q：GPL-2.0 到底能不能用？**
- 抄代码（复制函数/文件）→ 衍生作品 → 你的项目必须 GPL-2.0【存在风险】；
- 学机制（论坛/主持人/字数预算/IR）→ 思想不受版权保护 → 合法【安全】。
裁决：**零代码复制，纯模式移植**；如需引用其论坛协议设计文档，注明出处。

**Q：Flask + 轮询论坛会不会是性能黑洞？**
其规模（单用户分析任务）下够用；WorkFleet 的总控会议需高并发 → 用事件驱动（Go/Rust channel 或 Redis Stream）实现同构论坛总线，保留"发言-主持-指导-收敛"语义，不保留其 Flask 实现【设计裁决】。

## 6. 结论

BettaFish 的价值浓缩为一个词：**ForumEngine**——中文生态里少见的、完整公开的"多 Agent + LLM 主持人多轮收敛"机制，与用户总控模式的语义高度同构（把关/归纳/统一意见/分派）。次要资产：字数预算、报告 IR、SSE 流式。约束：GPL-2.0 只可学不可抄；Flask 同步架构需事件驱动重实现。定位：**总控模式会议机制的语义蓝本**（报告 12 的机制来源之一）。
