## 5. 苏格拉底追问与双向钢人（针对本表的核心判断）

**判断 J1：“没有项目 ≥ 80%，必须组合 + 自研。”**
- 凭什么？统一口径折算 + §3.2 七项“无人实现”。证据来自当前最新提交（各报告 SHA，`refs-commits.md`）。
- 反方最强：若用户接受“每个工具一个 bot 账号”“通知模式不要微信”“总控先不做”，CCC 的有效覆盖会超过 80%。
- 裁决：反方前提与原始需求的核心痛点（“只有一个常用微信”）直接冲突，且场景 3/4 明确要求总控与定时群发。J1 成立，`部分确认`（未运行任何候选）。

**判断 J2：“AFX 现有仓是承载仓的最佳候选。”**
- 凭什么？它已有单写者内核、事件 outbox、规划器、DAG、门禁、审批、预算、Vue 控制台、Windows 安装器、端口约定，且是用户自有代码（Proprietary，无许可证障碍）。
- 反方最强：AFX 只读了文档和目录，未运行；它的执行体是 CLI 无头模式，不是 ACP；与网关需要的“长连接 + 高并发 I/O”模型不同（同步 sqlite、单写者可能成为瓶颈）；版本号 0.4.0 与本研究“V0.0.1”的关系不清。
- 裁决：J2 作为**推荐前提**成立，但标 `部分确认`；需要在 PoC-0 读通 `fleet/kernel`、`fleet/runner` 并跑通测试后确认（见 `08`）。
