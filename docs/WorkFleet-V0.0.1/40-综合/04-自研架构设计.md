## 1. 设计目标与非目标

| 类别 | 内容 |
|---|---|
| 目标 G1 | 一个 IM 绑定被 N 个输入端复用（核心痛点） |
| 目标 G2 | 四模式（管理/通知/团队/总控）= 一张绑定表 + 策略，后台可视化配置 |
| 目标 G3 | 网关是两端对话的唯一事实来源，可按 fleet/agent/resume ID 查询 |
| 目标 G4 | 设备端常驻、零公网依赖；Hub 可选 |
| 目标 G5 | 高扩展：新 ACP Agent = 一条配置；新 IM = 一个适配器插件 |
| 目标 G6 | 高性能：网关内部开销远小于平台限流与 Agent 耗时（§16） |
| 非目标 | 不做通用聊天机器人；不替代各 Agent 自身的工具执行；不在 V1 前做多租户 SaaS |

## 2. 分层

```
L5  Admin UI（复用 AFX fleet/console/web，Vue3）      ← 四模式向导、绑定矩阵、扫码、历史、日程、订阅、总控、额度
L4  Admin API / Gateway API（FastAPI，挂在 AFX console 进程或独立）  ← REST + WebSocket 事件流
L3  Orchestration：Supervisor（总控，复用 AFX kernel/planner）· Scheduler · BroadcastPlanner
L2  Core：Router · CommandBus · PermissionBroker · SessionManager · Renderer · Outbox · RateLimiter/QuotaGuard · EventStore
L1  Adapters：InputAdapter（acp | stdio-custom | http-cloud | cli-oneshot）· ChannelAdapter（wechat-ilink | feishu | qq | dingtalk | discord | telegram）
L0  Infra：SQLite WAL（gateway.db）· SecretVault · AgentProcessPool · AdapterHost（插件子进程）· Metrics/Audit
外部：Agent 进程（claude-agent-acp、codex-acp、agent acp、openclaw acp、zcode、Coze 云）· IM 平台 · Hindsight（可选）· Hub（可选）
```

依赖规则（沿用 AFX `tests/architecture/test_import_boundaries.py` 的守门方式）：
- `fleet/gateway/core` 不 import 任何 adapter、console、supervisor；
- adapter 只依赖 `core.envelope`、`core.caps`、`infra`；
- supervisor 依赖 `core` 公开接口与 `fleet/kernel`，反之不允许；
- **变更**：Gateway 使用独立数据库 `data/gateway.db`，不与 `kernel.db`、`fleet.db` 共表（AFX 已有“两套存储互不干扰”的先例，`docs/架构.md §1`）。

## 3. 进程模型

| 进程 | 职责 | 数量 | 说明 |
|---|---|---|---|
| `fleet-gateway` | L1–L3 全部：通道连接、路由、出站、调度、命令、审批、总控编排 | 1（Edge 单实例） | Python 3.12 asyncio（Linux/macOS 可选 uvloop；Windows 用 Proactor 事件循环，以支持子进程管道） |
| `fleet-console`（已有） | Admin UI + Admin API | 1 | AFX 现有 FastAPI 进程（:3100）；通过本地 HTTP/WS 调 Gateway API |
| Agent 进程 | 每个 AgentProfile 一个常驻子进程（ACP 一连接多会话） | N | 由 `AgentProcessPool` 管理：空闲回收、崩溃重启、SIGINT 优先 |
| `fleet-adapter-host`（可选） | 第三方/实验适配器隔离运行 | 0–N | JSON-RPC over stdio（与 ACP 同形），崩溃不影响主进程 |
| `acp-sidecar`（C2′，可选） | 若 Python ACP SDK 不达标，用 Node 承载 ACP（官方 TS SDK 或 acpx runtime） | 0–1 | 对 Gateway 暴露统一 InputAdapter JSON-RPC |
| `fleet worker`（已有） | AFX 内核执行体；总控派工可复用 | 0–N | 与 Gateway 通过内核 API/事件交互 |
| Hindsight（可选） | 记忆/知识/分身 | 1 | Docker 或 pip；端口重映射见 §15 |
| `fleet-hub`（可选，云端） | 大规模广播、HTTPS 回调中继、多设备汇聚 | 1–N | 同代码库 `--role hub`，存储换 Postgres |

**单写者原则（继承 AFX）**：`gateway.db` 只有一个写协程（`DbWriter`，批量事务，默认每 10 ms 或 200 条 flush），其余组件通过 `asyncio.Queue` 提交写命令；读走独立只读连接池。这样既避免 SQLite 写锁竞争，又与 AFX 内核哲学一致。

## 4. 技术栈（推荐 + 理由）

| 层 | 选型 | 理由 | 备选 |
|---|---|---|---|
| 语言/运行时 | Python 3.12（AFX 要求 ≥3.11） | 复用现有内核/控制台/安装器（安装器已内置私有 Python + Node，`README` 方式一） | TS（C1） |
| Web | FastAPI + uvicorn（已有） | AFX 依赖即此 | — |
| 数据校验 | Pydantic v2 | 信封/配置/插件清单 schema；可导出 JSON Schema 进 AFX `packages/contracts` | — |
| 存储 | SQLite WAL（Edge）/ Postgres（Hub） | 设备零依赖；Hub 用 `FOR UPDATE SKIP LOCKED` 横向扩 worker（R5 §3.5 模式） | — |
| 全文检索 | SQLite FTS5 `trigram`（中文子串） | 本轮实验可命中中文（`01 §0.3`）；Orca 的 `unicode61` 对 CJK 只按单字切（R4 §3.5） | jieba 分词后写 FTS |
| ACP | `agentclientprotocol/python-sdk`（Apache-2.0） | 官方；与协议同步 | Node 旁车：官方 TS SDK / acpx |
| IM SDK | `lark-oapi`、`dingtalk-stream`、`botpy`（或自写）、`aiogram`、`discord.py`、微信 iLink 自写（httpx） | 官方/主流，MIT（`02 §0`） | — |
| HTTP 客户端 | httpx（async，HTTP/2 可选） | 长轮询与 REST 统一 | aiohttp |
| 调度 | 自研规则引擎 + holiday-cn 数据 | 现成库都不支持调休 | — |
| 加密 | `cryptography`（AES-256-GCM）+ `keyring`（OS 钥匙串） | 信封加密 | Argon2id 口令派生（无钥匙串时） |
| 可观测 | Prometheus 文本 `/metrics`；OpenTelemetry（可选） | 本地零依赖 | — |
| 前端 | Vue3（AFX 现有） | 复用 | — |

## 5. 统一消息信封（继承 P4 §2，Python 化）

```python
# fleet/gateway/core/envelope.py（设计）
from typing import Literal, Optional, Any
from pydantic import BaseModel, Field

Kind = Literal[
  "msg.text","msg.delta","msg.final","thought.delta",
  "tool.start","tool.update","tool.end","plan.update","usage.update","session.info",
  "perm.request","perm.decision","cmd","turn.end","error","notice",
  "schedule.fire","broadcast",
  "sv.meeting","sv.dispatch","sv.report","sv.escalation"     # 变更：总控事件（见 05）
]

class EndpointRef(BaseModel):
    family: Literal["agent","channel","scheduler","supervisor","system"]
    adapter_id: str                 # acp:claude / wechat-ilink
    account_id: Optional[str] = None
    peer_id: Optional[str] = None
    device_id: Optional[str] = None

class ConvRef(BaseModel):
    fleet_session_id: str
    agent_session_id: Optional[str] = None   # ACP sessionId / Codex thread / Coze conversation
    channel_thread_id: Optional[str] = None
    turn_id: Optional[str] = None

class Part(BaseModel):
    type: Literal["text","image","file","diff","card"]
    text: Optional[str] = None; format: Optional[Literal["plain","markdown"]] = None
    uri: Optional[str] = None; mime: Optional[str] = None; name: Optional[str] = None; size: Optional[int] = None
    path: Optional[str] = None; unified: Optional[str] = None
    card_ref: Optional[str] = None; fallback_text: Optional[str] = None

class Action(BaseModel):
    id: str; label: str
    kind: Literal["allow_once","allow_always","reject_once","reject_always","custom"]
    reply_token: Optional[str] = None        # 无按钮渠道：Y1/N

class Envelope(BaseModel):
    v: Literal[1] = 1
    id: str                                   # ULID
    ts: str                                   # UTC ISO-8601
    dir: Literal["in","out"]
    kind: Kind
    src: EndpointRef
    dst: list[EndpointRef] = Field(default_factory=list)   # Router 填充
    conv: ConvRef
    parts: list[Part] = Field(default_factory=list)
    actions: list[Action] = Field(default_factory=list)
    perm: Optional[dict[str, Any]] = None
    prio: Literal["p0","p1","p2","p3"] = "p2"
    ttl_ms: Optional[int] = None
    dedupe_key: Optional[str] = None
    corr: Optional[str] = None
    binding_id: Optional[str] = None          # 变更：命中的绑定（审计/调试）
    route_trace: list[str] = Field(default_factory=list)   # 变更：路由决策链，防环（max_hops）
    sv_run_id: Optional[str] = None           # 变更：总控运行 ID
    meta: dict[str, Any] = Field(default_factory=dict)
```

ACP `session/update` → `kind` 的映射表沿用 P4 §2.1，不重复。

## 6. 数据模型（SQLite DDL，`data/gateway.db`）

> 约定：主键 ULID 文本；时间 UTC ISO-8601 文本；JSON 列为 TEXT（`json_valid` CHECK）；所有密钥只存 `secret.id` 引用。Hub 上同构迁移到 Postgres（JSON→JSONB、TEXT 时间→TIMESTAMPTZ）。

```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;
PRAGMA busy_timeout=5000;

CREATE TABLE schema_version (version INTEGER PRIMARY KEY, applied_at TEXT NOT NULL);

-- ===== 设备与密钥 =====
CREATE TABLE device (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, os TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'edge' CHECK (role IN ('edge','hub')),
  last_seen_at TEXT, created_at TEXT NOT NULL
);
CREATE TABLE secret (

  kind TEXT NOT NULL CHECK (kind IN ('bot_token','app_secret','api_key','oauth','webhook_secret','other')),

  role TEXT NOT NULL DEFAULT 'member' CHECK (role IN ('owner','admin','member','subscriber','blocked')),

-- ===== 路由：绑定表（四模式）=====
CREATE TABLE binding (
  id TEXT PRIMARY KEY, name TEXT NOT NULL,

  direction TEXT NOT NULL DEFAULT 'both' CHECK (direction IN ('both','in-only','out-only')),
  reply_target TEXT NOT NULL DEFAULT 'last-active' CHECK (reply_target IN ('last-active','pinned','ask','supervisor')),
  pinned_profile_id TEXT REFERENCES agent_profile(id),
  filter_json TEXT NOT NULL DEFAULT '{}',   -- {kinds:[],minPrio:'p2',tags:[]}

  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE TABLE binding_input (
  binding_id TEXT NOT NULL REFERENCES binding(id) ON DELETE CASCADE,
  selector TEXT NOT NULL,                   -- profile:<id> | tag:<t> | sv:<run> | sched:<id> | *

CREATE TABLE binding_output (

-- ===== 会话 =====
CREATE TABLE fleet_session (
```

## 7. Router：四模式 = 绑定表 + 策略

### 7.1 编译与匹配
- 启动及每次配置变更时，把 `binding/binding_input/binding_output` 编译成两个内存索引：
  - **出站索引** `profile_id → [(binding, outputs)]`（tag 选择器展开为 profile 集合）；
  - **入站索引** `(account_id, peer_id) → [binding]`（`sub:` 选择器展开为订阅集合，按需懒加载）。
- 匹配复杂度 O(命中绑定数)；编译结果带版本号，热更新原子替换（参考 OCL 路由缓存 `resolve-route.ts:283-300`）。
- 防环：`route_trace` 长度 > `max_hops` 即丢弃并记 `error`（参考 PPC `max_hops 1..8`）。

### 7.2 入站决策（IM → 输入端）

```
inbound(env):
  principal = upsert im_principal; refresh ctx(context_token/sessionWebhook/msg_id); quota_state.reset_inbound_window()
  if env.text startswith '/' and CommandBus.match(env) → handle command; return
  if PermissionBroker.match_reply_token(env) → decide permission; return
  bindings = inbound_index[(acct, peer)]  (按 priority)
  b = first enabled in bindings
  match b.mode:
    supervisor   → Supervisor.inbox(env)            # 用户与总控对话（不打断执行）
    notification → 订阅者回复：进入其独立 fleet_session（可选交给 FAQ Agent）
    management|team →
        target = alias_prefix(env) or reply_cursor.current or (b.pinned) or ask_user()
        session = SessionManager.get_or_create(target, acct, peer, b)
        enqueue_turn(session, env)   # 会话互斥：同会话同时 1 个 turn，其余排队并回执“已排队第 N 位”
```

### 7.3 出站决策（输入端 → IM）

```
outbound(env from agent/supervisor/scheduler):
  persist event
  for (b, outputs) in outbound_index[env.src]:
     if b.mode == 'supervisor' and env.src.family=='agent': Supervisor.review(env); continue   # 必经总控把关
     if not b.filter.accepts(env): continue
     for o in outputs where prio(env) >= o.min_prio:
        peers = expand(o.peer_selector)        # owner / group / sub:<group>
        rendered = Renderer.render(env, caps(o.account), b.render)
        Outbox.enqueue(o.account, peers, rendered, env.prio, ttl, dedupe)
```

### 7.4 四模式配置样例

| 模式 | binding | inputs | outputs | reply_target |
|---|---|---|---|---|
| 管理 | `mgmt-wechat` | `tag:all`（alias：claude-a、codex-a、cursor-b…） | `wechat:me / owner (primary)`；`feishu:me (fallback)` | last-active（`/use` 置顶） |
| 通知 | `ai-daily` | `sched:ai-daily`、`profile:news-agent` | `telegram:bot / sub:ai-daily`、`feishu:corp / sub:ai-daily` | — （direction=out-only；回复进各自会话） |
| 团队 | `lineA`、`lineB`、`corp` | `tag:lineA` / `tag:lineB` / `tag:corp` | 微信 / QQ / 飞书 | 各自 last-active |
| 总控 | `sv-main` | `tag:projectX`（员工） | 飞书或微信 owner | supervisor |

## 8. 出站流水线、限流与配额

1. **Renderer**：降级链 `card → markdown → plain`；按 `maxTextLen` 切分；`diff` 在不支持文件的渠道折叠为摘要 + “回复 `/diff N`”；流式策略按 `streamingEdit`（飞书/钉钉卡片流式 300–800ms 一次；`edit-message` 节流；`none`（微信）只发最终 + 超过 60s 发一次进度）。（P4 §6）
2. **Outbox**：至少一次投递 + `dedupe_key` 幂等；`ttl` 过期丢弃并记录；状态机 `queued→sending→sent|failed|expired|deferred`。
3. **RateLimiter（三级令牌桶）**：`adapter → account → peer`；桶状态每 5s 落 `rate_bucket`（重启不突发）；收到平台 429/限流码时以 `retry_after` 冻结对应桶。预设沿用 P4 §6 表。
4. **QuotaGuard**：微信 `inbound_window`（默认 capacity=10，窗口 24h，`部分确认`，可配）；QQ `daily`（1000/用户/天，新版文档）；剩余 ≤3 时附“回复任意字续期”；耗尽 → `fallback` 输出或合并摘要等待下次入站；p0 可动用保留额度（默认保留 2）。
5. **优先级调度**：每个 account 一个优先队列；p0 抢占；p3 在额度紧张时合并为日报。
6. **广播**：BroadcastPlanner 把 job 拆成 `broadcast_delivery`，按渠道吞吐预算计算窗口（例：TG 30/s，10 万人约 56 分钟，P3 §7），在 8:55–9:05 平滑或按时区分桶。

## 9. 会话模型与命令系统

### 9.1 会话
- `fleet_session` 三元映射：`(fleet_session_id) ↔ (profile, agent_session_id) ↔ (account, peer)`；resume ID 命名空间属于 Agent（P1 §6）。
- 互斥：`(profile_id, agent_session_id)` 同时最多 1 个 turn（Claude 同会话并发会交错写 transcript；Coze 同 conversation 并发 4016）。
- 生命周期：`active → idle(N 分钟) → closed`；进程级空闲回收（SIGINT 优先）。
- 冷启动恢复：优先 `session/resume`（不回放，历史由事件库提供）；无该能力且有 `loadSession` 时 `session/load` 补数；都没有则新开并在 IM 提示。

## 10. 审批（PermissionBroker）

流程沿用 P4 §7：`session/request_permission` → `perm.request(p0, ttl=10min)` → 有按钮渠道渲染按钮（飞书 3 秒内 `ack`，再异步回 ACP），无按钮渠道渲染 `Y1/Y2/N` 口令 → 校验（发起者权限、过期、已决）→ 按 `optionId` 回复。
补充：
- 风险分级：工具名/命令模式规则（如 `rm -rf`、网络外发、凭据文件路径）→ `high` 只允许 owner 审批，且禁止“总是允许”。
- 复用 AFX `governance/approval.py` 的存储与审批中心页面（`ApprovalCenterPage`），IM 只是另一个审批入口。
- 无人值守（定时任务）默认 `deny-unattended`；CLI 一次性通道只能预授权（P4 §3.1）。

## 15. 安全

| 主题 | 设计 |
|---|---|
| 密钥加密 | 信封加密：每条密钥随机 DEK（AES-256-GCM），DEK 用主密钥 KEK 加密；KEK 存 OS 钥匙串（Windows Credential Manager/DPAPI、macOS Keychain、Linux Secret Service，经 `keyring`）；无钥匙串时用 Argon2id 从启动口令派生。`secret.key_version` 支持轮换。修复 WCB“token 明文”（R1 缺陷 6.3）。 |

| 数据最小化 | 订阅者只存平台 ID 与时区；保留期可配；导出/删除接口（个人信息合规细节 `证据不足`，需法务）。 |

## 18. 5W1H、追问与钢人（针对本架构）

- **What**：Python 单进程异步网关 + 单写者 SQLite + 插件化适配器 + 复用 AFX 内核与控制台。
- **Why**：把“每工具独占 IM 绑定”变为“网关独占、多路复用”，并让四模式只是绑定表的不同写法。
- **Where/When**：Edge 常驻；Hub 按需；PoC 后实施。
- **Who**：Gateway 核心、各适配器 owner、总控 owner；用户配置绑定。
- **How**：§2–§15。
- **What if**：单写者成为瓶颈 → 批量参数调大，或把 event 分库（按月）；Python SDK 不足 → C2′；某渠道 SDK 停更 → 插件替换不动核心；多设备 → Hub 汇聚，Edge 间不直连。

**追问**：“单 SQLite 单写者能否撑住？”——个人/小团队场景下，入站消息量受人类输入与平台限流约束（每秒个位数到数十条），Agent 流式 delta 在内存合并后入库；广播放 Hub/Postgres。反方：大量 Agent 并发流式 + 全量落库可能写放大 → 已规定“delta 合并后存、原始 delta 不存”。结论 `部分确认`，PoC-9 压测。

**钢人反方**：“为何不直接用 AFX 的 kernel.db 存网关数据？”——支持：一个库更简单。反对：内核是任务语义（goal/todo），网关是消息语义，生命周期与写入频率完全不同，混用会让内核迁移与网关迁移互相牵制。裁决：分库，经事件和 API 交互（与 AFX 现有“两套存储互不干扰”一致）。
