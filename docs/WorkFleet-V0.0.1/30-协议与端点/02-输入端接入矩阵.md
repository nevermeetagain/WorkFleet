## 0. 一页结论

| 输入端 | 首选接入方式 | 备选 | 会话 ID 来源 | 历史落盘位置 | "新开对话"等价物 | 关键风险 |
|---|---|---|---|---|---|---|
| **Claude Code** | ACP 适配器 `claude-agent-acp`（Claude Agent SDK） | `claude -p --output-format stream-json --resume <id>` | Agent SDK `session_id`（UUID） | `~/.claude/projects/<cwd转义>/<session-id>.jsonl`（默认保留 30 天） | ACP `session/new`；CLI 中 `/clear` | 适配器版本漂移；`-p` 会话不出现在 picker（但可按 ID 恢复） |
| **Codex CLI** | ACP 适配器 `codex-acp` | `codex exec --json` / `codex exec resume <ID>`；`codex app-server` | thread id（UUID，服务端生成） | `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<ts>-<id>.jsonl` + `state_*.sqlite` 索引 | ACP `session/new`；`codex exec` 不带 resume | `codex exec` 默认只读沙箱；需 Git 仓库（可 `--skip-git-repo-check`） |
| **Cursor** | 原生 ACP `agent acp` | `agent -p --output-format stream-json --resume <chatId>` | chatId | `证据不足`（官方未写明路径） | `session/new` / `agent create-chat` | 不回复 permission 会阻塞；团队级 MCP 在 ACP 模式不可用 |
| **OpenClaw** | 原生 ACP 桥 `openclaw acp`（stdio↔Gateway WS） | Gateway WebSocket 协议 / OpenAI 兼容 HTTP | Gateway session key（如 `agent:main:main`）；默认 `acp-bridge:<uuid>` | `~/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite` | `--reset-session` / `_meta.resetSession` / 聊天中 `/new` `/reset` | 自身就是"多渠道网关"，与本产品功能重叠；per-session `mcpServers` 不支持 |
| **ZCode（智谱 Z.ai）** | 自定义适配器驱动 `zcode app-server --stdio`（私有协议） | `zcode -p "<prompt>"`；社区 `zcode-acp`（非官方） | app-server 内存会话 | `~/.zcode/`（配置/规则/技能）；会话持久化 `证据不足` | `session/create` | 官方协议**非 ACP**、未文档化；社区称会话不能跨进程恢复 |
| **Coze（扣子）** | HTTP 适配器：OpenAPI `POST /v3/chat`（SSE 流） | 官方 SDK（coze-js / coze-py / coze-go） | `conversation_id` + `chat_id` | 云端（Coze 平台） | 新建 conversation 或 `/v1/conversations/{id}/clear` | 云端执行、无法操作本地代码；同会话同时只能 1 个进行中 chat（错误码 4016） |

**结构性结论**：6 个目标输入端分为三类协议族——**ACP 族**（Claude/Codex/Cursor/OpenClaw）、**私有 stdio 族**（ZCode）、**云 HTTP 族**（Coze）。InputAdapter 必须以"协议族"为一级抽象，而不是以"产品"为抽象（见 04）。`已确认`

## 1. Claude Code

### 1.1 驱动方式
- **ACP**：`npx @agentclientprotocol/claude-agent-acp@0.91.0`（ACP Registry `claude-acp`）。适配器基于 `@anthropic-ai/claude-agent-sdk@0.3.300`（`/workspace/work/refs/claude-code-acp/package.json`）。能力：`loadSession: true`，`sessionCapabilities {fork, list, resume}`（`src/acp-agent.ts` L2889–2928）。`已确认`
- **CLI 无头**（https://code.claude.com/docs/en/headless）：`已确认`
  - `claude -p "<prompt>"`；`--output-format text|json|stream-json`；流式需 `--verbose --include-partial-messages`；`stream-json` 最后一行是 `result`（含 `session_id`、成本）。
  - 续接：`--continue`（最近）/ `--resume <session-id>`（可跨目录按 ID 找；也接受 `.jsonl` 绝对路径）；`--fork-session` 分叉。
  - 权限：`--allowedTools`、`--permission-mode auto|dontAsk|acceptEdits|…`、`--permission-prompts none`（无人值守，v2.1.259+）、`--permission-prompt-tool`（把审批交给 MCP 工具——可作为 IM 审批的 CLI 路径）。
  - `--bare`：跳过 hooks/skills/MCP/CLAUDE.md 自动发现，需 `ANTHROPIC_API_KEY`（不读 OAuth/钥匙串）。
  - 结束：SIGTERM 退出码 143 且不记录本轮结果；要优雅结束应先 SIGINT 或 SDK `interrupt()`。
- **Agent SDK（TS/Python）**：最强控制面（`canUseTool` 回调、原生消息对象）。

### 1.2 会话与历史（https://code.claude.com/docs/en/sessions）`已确认`
- 存储：`~/.claude/projects/<project>/<session-id>.jsonl`，`<project>` 为 cwd 非字母数字替换为 `-`，超 200 字符截断+哈希；可用 `CLAUDE_CONFIG_DIR`、`CLAUDE_CODE_PROJECT_DIR_NAME` 改；保留期 `cleanupPeriodDays` 默认 30 天；`--no-session-persistence` 禁止写入。
- **官方明确警告**：JSONL 条目格式为内部格式、随版本变化，**不要直接解析**，应使用 `/export` 或脚本接口（`-p --output-format json`、hooks 的 `transcript_path`、Agent SDK）。→ 对"两端对话记录查看"的设计含义：**以网关流经数据为准**，Claude 的 JSONL 只作"冷数据导入"且需容错。
- `/clear`：开空上下文，旧会话保存可 `/resume`。`-p`/SDK 创建的会话不出现在 picker 与 `--continue`，但 `--resume <id>` 可用。
- 同一会话在两个终端同时恢复（不 fork）→ 消息交错写入同一 transcript。→ 网关必须对 **(agent, session) 加互斥锁**。

### 1.3 并发与认证
- 认证：订阅 OAuth（交互登录）或 `ANTHROPIC_API_KEY`；Bedrock/Vertex 等走各自凭据。`已确认`
- 并发上限：受 Anthropic 账户速率/订阅额度限制，官方无"同时会话数"数字。`证据不足`

## 2. Codex CLI

### 2.1 驱动方式
- **ACP**：`npx @agentclientprotocol/codex-acp@2.2.2`（Registry）。源码结构参考 `/workspace/work/refs/codex-acp/src/codex_agent.rs`：`load_session`、`resume_session`、`list_sessions`（按 `UpdatedAt` 倒序分页，过滤来源 Cli/VSCode/Unknown）。⚠️ 本地克隆版本 0.16.0 与 Registry 2.2.2 不一致。`部分确认`
- **CLI 无头**（https://developers.openai.com/codex/noninteractive）：`已确认`
  - `codex exec "<task>"`；进度走 stderr，最终消息走 stdout；`--json` 输出 JSONL 事件：`thread.started{thread_id}`、`turn.started`、`turn.completed{usage}`、`turn.failed`、`item.*`、`error`。
  - 续接：`codex exec resume --last "<prompt>"` 或 `codex exec resume <SESSION_ID>`。
  - 沙箱：默认只读；`--sandbox workspace-write` / `danger-full-access`；`--full-auto` 已移除，改 `--approve-for-me`。
  - `--ephemeral` 不落盘；`-o/--output-last-message`；`--output-schema` 结构化输出。
  - 必须在 Git 仓库内，或 `--skip-git-repo-check`。
  - 认证：复用 `codex login`；CI 用 `CODEX_API_KEY`（仅对该次调用注入）。
- **App Server**：`codex app-server`（JSON-RPC），OpenClaw 的 Codex harness 即基于它（https://docs.openclaw.ai 目录 "Codex app-server transport"）。可作为 ACP 之外的二级通道。`部分确认`（未读其协议文档全文）

### 2.2 会话与历史 `部分确认`（官方文档提及 `~/.codex/sessions`；细节来自社区与源码）
- `${CODEX_HOME:-~/.codex}/sessions/YYYY/MM/DD/rollout-<YYYY-MM-DDThh-mm-ss>-<thread_id>.jsonl`；归档在 `archived_sessions/`；常量 `SESSIONS_SUBDIR="sessions"`、`ARCHIVED_SESSIONS_SUBDIR="archived_sessions"`（https://raw.githubusercontent.com/openai/codex/main/codex-rs/rollout/src/lib.rs）。
- `codex resume <id>` 通过 `state_*.sqlite` 的 `threads` 表查 `rollout_path`，**不扫描 JSONL**（社区工具 casr 源码注释）；会话 ID 由服务端生成、不可通过 CLI 指定。
- 按日期而非项目分目录 → 按项目检索需读每个文件首行 `session_meta.cwd`。
- 恢复时会写**新的** rollout 并回放旧条目 → 同一逻辑会话可能对应多个文件，去重需用 `session_id` + `parent_thread_id`（社区分析，`部分确认`）。

### 2.3 并发
- 官方无会话并发上限数字；受 ChatGPT 计划额度/API 速率限制。`证据不足`

- **ACP 原生**：`agent acp`（https://cursor.com/docs/cli/acp）。流程：`initialize` → `authenticate{methodId:"cursor_login"}` → `session/new | session/load` → `session/prompt` → 处理 `session/update` 与 `session/request_permission`（回复 `allow-once` / `allow-always` / `reject-once`）→ `session/cancel`。`已确认`

## 4. OpenClaw

### 4.1 定位提醒（重要）
OpenClaw 本身是"多渠道 AI 网关"：内置 Feishu、QQ bot、WeChat（腾讯外部插件）、Telegram、Discord、钉钉以外的大量渠道，并支持多 Agent 路由、cron 自动化、ACP Agents（用 `acpx` 拉起 Codex/Claude/Gemini）。它与 AideanFleet 的目标高度重叠——这是"先找开源项目"研究方向必须正视的竞品/底座候选（由其他研究方向评估，此处仅记录接入事实）。`已确认`（https://docs.openclaw.ai 导航）

### 4.2 作为输入端的驱动方式（https://docs.openclaw.ai/cli/acp）`已确认`
- `openclaw acp`：ACP over stdio，内部转发到 Gateway WebSocket；`--url wss://host:18789 --token-file …`；`--session <key>` / `--session-label` / `--require-existing` / `--reset-session`；`--provenance off|meta|meta+receipt`。
- 兼容矩阵：`initialize/newSession/prompt/cancel` 实现；`listSessions`、斜杠命令（`available_commands_update`）实现；`resumeSession/closeSession` 实现；`loadSession` **部分**（仅桥接创建的会话完整回放，16 MiB 预算）；per-session `mcpServers` **不支持**（会报错）；客户端 fs/terminal 不使用；exec 审批通过 `session/request_permission` 中继。
- 局限：多个 ACP 客户端共享同一 Gateway session key 时事件/取消路由为 best-effort；usage 为近似值。
- 安全：`--token` 会出现在进程列表，优先 `--token-file` 或环境变量 `OPENCLAW_GATEWAY_TOKEN`。

### 4.3 会话与历史（https://docs.openclaw.ai/reference/session-management-compaction/store 、/concepts/session）`已确认`
- 运行时会话行与 transcript：`~/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite`；遗留 `~/.openclaw/agents/<agentId>/sessions/`。
- transcript 为追加写、树结构（`id`+`parentId`）。
- 重置：聊天中 `/new`、`/reset`；配置 `session.reset.mode: daily(atHour)|idle(idleMinutes)`；`session.dmScope`（如 `per-channel-peer`）。

## 5. ZCode（智谱 Z.ai 官方 ADE）

### 5.1 产品事实
- 官方仓库 https://github.com/zai-org/ZCode（v3.15.1，2026-10-10 更新）；提供桌面、Web、终端 Agent；`zcode` 无参进入 TUI、`--web` 启动 Web、其他参数交给 Agent CLI。`已确认`
- 官方文档 https://zcode.z.ai/cn/docs ：深度适配 GLM-5.3；**自带 Bot Channel（飞书/微信/Telegram）与手机 Remote 控制**；配置在 `~/.zcode/v2/config.json`、全局规则 `~/.zcode/AGENTS.md`、`~/.zcode/{agents,skills,commands}/`。`已确认`

### 5.2 驱动方式
- `zcode -p "<prompt>"`：无头单次。`部分确认`（来自 multica issue #5361 与社区页面；官方 CLI 参考页未读到全文）
- `zcode app-server --stdio`：NDJSON，**无 `jsonrpc` 字段**（带上会被拒），**无 initialize 握手**；方法观测：`session/create`（需 `workspace` 对象）、`session/event`（通知）、`session/resume`、`session/messages`、`session/setThoughtLevel`；后续社区 PR 记录完整流程 `session/create|resume → session/subscribe → session/send → 消费 session/event（model.streaming / tool.updated / turn.completed|failed）→ session/close`，并称**会话仅存在于 app-server 进程内存、不能跨进程恢复**，且通知可能丢失需轮询 `session/read`。`部分确认`（来源：https://github.com/multica-ai/multica/issues/5361 ，社区逆向，非官方文档）
- 社区 ACP 包装：`zcode-acp`（william0wang、supermomonga 等，自述 "Unofficial"，并提示可能违反 ToS）；Registry 另有 `glm-acp-agent`（直连 GLM Coding Plan，非 ZCode 本体）。`已确认`（存在性）

### 5.3 设计含义
- ZCode 适配器标记为 **experimental**，协议字段做"宽进严出"校验，长驻单进程复用会话；`/clear` = `session/close` + `session/create`。
- ZCode 自带微信 Bot：若用户同时启用 ZCode 自带 Bot 与 AideanFleet，会**争抢同一个微信 ClawBot 绑定**（见 03 §2 的 1:1 绑定约束）——应在接入向导中提示关闭 ZCode 内置 Bot Channel。`部分确认`（推断，依据 03 的绑定约束）

## 6. Coze（扣子 / coze.cn；国际版 coze.com）

### 6.1 定位
Coze 是**云端智能体平台**，不是本地编码 CLI；它不能读写用户本地仓库。在本产品中更适合"运营/推广/数据汇总"类输入端（场景示例 2），而非编码。`已确认`

### 6.2 驱动方式（https://docs.coze.cn/developer_guides_chat_v3 、https://www.coze.com/open/docs/developer_guides/chat_v3）`已确认`
- `POST https://api.coze.cn/v3/chat`（国际 `api.coze.com`），Header `Authorization: Bearer <PAT 或 OAuth token>`；Body：`bot_id`、`user_id`、`stream`、`auto_save_history`、`additional_messages[]`、`custom_variables`、`parameters`。Query：`conversation_id`（可选，不传则自动生成）。
- 非流式：轮询 `GET /v3/chat/retrieve?conversation_id&chat_id`，再 `GET /v3/chat/message/list` 取消息。
- 会话：`POST /v1/conversation/create`（可预置消息）；`/v1/conversations/{conversation_id}/clear` 创建新的上下文片段，使后续 chat 忽略之前的消息 → **`/clear` 的精确等价物**。
- 约束：**同一 conversation 只能有 1 个进行中的 chat，否则 4016**。→ 网关需对 conversation 串行化。
- 端插件：`status=requires_action` 时通过 `/v3/chat/submit_tool_outputs` 回传结果（可用来把"审批"做成端插件）。
- 速率限制/配额：`证据不足`（未读到官方数值）。
- 开源版：Coze Studio（https://github.com/coze-dev/coze-studio ）提供同形 API，可私有化。`已确认`（Wiki API 参考存在）

## 8. 5W1H

- **What**：六个输入端在"如何驱动、如何续接、如何新开、历史在哪"四个维度差异巨大；ACP 统一了其中四个的驱动与会话语义。
- **Why**：用户需要"在一个 IM 里控制多个工具、按 session 查历史、/clear 新开"。若逐个解析各家私有历史文件，会被版本变化反复打断（Claude 官方已明确警告）→ 根本解法是**网关作为唯一事实来源**（事件溯源），本地文件仅作导入。
- **Where/When**：ACP/ZCode/CLI 类必须在代码所在设备运行（Edge）；Coze 可在任意有网的位置（Hub 即可）。会话恢复必须在 `initialize` 后、`prompt` 前。
- **Who**：Agent 厂商（Anthropic/OpenAI/Cursor/OpenClaw 基金会/Z.ai/字节）；适配器维护方（agentclientprotocol 组织、社区）；用户负责各工具登录。
- **How**：三类 InputAdapter（`acp`、`stdio-custom`、`http-cloud`）+ 一类兜底 `cli-oneshot`（`-p`/`exec` + `--resume`），统一产出 04 定义的事件信封。
- **What if**：
  - 某工具升级打破适配器 → capability 探测失败时自动降级到 `cli-oneshot`（Claude/Codex/Cursor 都有 `-p + --resume`）。
  - 用户未登录 → `initialize` 返回 `authMethods` 且后续报认证错误 → 通过 IM 推送"请在设备上执行 `claude /login` / `codex login` / `agent login`"。
  - 用户想要多个 Agent 共享上下文（总控"开会"）→ 各 Agent 会话互相独立，必须由网关摘要转述，不存在协议级共享。

## 9. 苏格拉底追问 & 钢人论证（节选关键结论）

**结论 A：Claude/Codex 用 ACP 适配器优于直接 `-p`。**
- 追问：适配器多一跳，凭什么更好？→ 证据：适配器提供常驻会话、权限往返、list/resume，`-p` 每轮冷启动且权限只能预授权或经 MCP 工具。
- 反方最强论点：`-p` 是官方一等接口，版本同步最及时；适配器（尤其 codex-acp）存在版本号混乱。
- 裁决：**双通道**——ACP 为主，`-p/exec` 为降级与批处理（定时任务、无人值守）通道。

**结论 B：ZCode 只能走私有协议。**
- 追问：是否有官方 ACP？→ 搜索结果仅见社区 zcode-acp 与 multica 逆向；ZCode 官方 README 未提及 ACP。
- 反方：社区适配器已可用，何必自己写？→ 社区包自述可能违反 ToS，且依赖未文档化接口。
- 裁决：V0.0.1 先用 `zcode -p` 一次性模式（最稳），app-server 长连接列为实验特性。`部分确认`

**结论 C：Coze 适合作"非编码输入端"。**
- 追问：用户把 Coze 列为"ACP 软件"是否有误？→ Coze 官方接口是 HTTP OpenAPI，无 ACP 证据。
- 裁决：保留 Coze，但在 UI 中标注"云端智能体（不可操作本地代码）"。

## 10. 最终判断

- **结论**：输入侧按协议族实现 4 类适配器；ACP 覆盖 Claude/Codex/Cursor/OpenClaw；ZCode、Coze 专用。
- **前提**：各工具在设备上已安装并登录；网关具备会话互斥与事件落库。
- **局限/未验证**：Cursor 本地历史路径、ZCode 持久化、Coze 速率限制、各工具并发上限均 `证据不足`；未做端到端实测。
- **风险**：OpenClaw 与本产品定位重叠（可能更适合作为底座而非输入端，需开源评估结论）；ZCode 私有协议变动。
- **下一步**：实测矩阵 §7 中所有 `证据不足` 项；把各工具 `available_commands_update` 实际返回的斜杠命令清单落表，确认 `/clear` 透传还是网关拦截。
- **是否进入下一阶段**：允许（接口设计以能力位驱动，未确认项默认关闭）。
