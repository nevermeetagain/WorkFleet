# SOL-001：WorkFleet v1 交付方案

## 1. 基本信息
- 来源需求：`02_requirements/product-requirements.md` 全部 MUST/SHOULD
- 架构：`03_solution/architecture.md`；决策 ADR-001…014

## 2. 问题定义
多个本机编码智能体与多个 IM/Web 接收方之间缺少统一、可审计、可总控的路由层；用户被迫反复扫码换绑。

## 3. 方案目标
一次扫码（或不接 IM）即可在任一入口与任意本机智能体对话、审批、查记录；支持管理/通知/团队/总控四模式与多用户公司场景。

## 4. 方案描述
### 4.1 总体思路
本机节点 + 云中转 + 契约包；按 11 个垂直切片 S0–S10 交付（`04_planning/slices.md`）。
### 4.2 关键步骤
S0 步行骨架 → S1 真实 ACP + Web → S2 微信 → S3 组织结构 → S4/S5/S6 并行铺开 → S7 公司能力 → S8/S9 总控 → S10 收尾验收。
### 4.3 输入
契约冻结包、迁移 0001、任务卡 84 张。
### 4.4 输出
`apps/relay`、`apps/node`、`apps/web`、`packages/contracts`、`packages/testkit`、`infra/`、测试与证据。

## 5. 技术选型与决策引用
ADR-002 契约、ADR-003 SQLite、ADR-004 Monorepo、ADR-005 协议、ADR-006 鉴权、ADR-007 输入、ADR-008 前端、ADR-009 后端栈、ADR-010 IM、ADR-013 总控模型、ADR-014 PWA。

## 6. 约束与假设
REQ-C-001…009；假设见 `00_governance/assumptions.md`。

## 7. 影响范围
全新仓库代码；不影响旧内部项目（DEC-027）。

## 8. 风险
见 `00_governance/risks.md`（R-01 微信限额、R-02 ZCode、R-03 范围）。

## 9. 验收标准
