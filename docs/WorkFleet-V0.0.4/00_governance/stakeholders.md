# 角色与责任

## 1. 人类角色
| 角色 | 是谁 | 在系统中的身份 | 职责 | 拥有的决定权 | 依据 |
|---|---|---|---|---|---|
| 用户本人（发起人 / 产品负责人） | 仓库所有者，开发者，日常并发使用 5 个以上开发工具，只有一个常用微信 | 画像 P1（微信 + 本机开发 CLI）；自己中转的组织 admin；自己设备的所有者 | 提出与裁定需求；裁定 U-08 工期人力、券超额、所有权偏离等待定项；部署个人中转；真机冒烟（扫码、手机端操作） | 需求范围终裁；推翻任一 DEC/ADR；批准 opus/fable 超额券 | 原始说明书；DEC-039/050；QA-01…27 |
| 朋友 | 与用户共用中转（暂定）的另一位用户 | 画像 P2（飞书 + 外部智能体，首个为 OpenClaw）；同一中转上的独立组织 | 用自己的飞书企业自建应用接入；在自己电脑运行本机节点；反馈 P2 体验 | 自己组织内的配置；若有合规要求可触发 DEC-039 反转（改用独立中转） | DEC-035/039；QA-06/07/09 |
| 老板 | 场景 2 的管理者 | 公司组织内的接收人（飞书等），控制台角色通常为 viewer | 接收汇总、审批重大事项；只看授权字段 | 审批（高风险只允许 owner 批，DEC-011） | 场景 2；DEC-047；QA-19 |
| 部门（如数据分析部） | 场景 2 的业务接收方 | 公司组织内的接收人；operator 或 viewer | 接收明细数据与分析结果；按接收人 × 业务线 × 字段规则看数据 | 本部门绑定的日常处理 | 场景 2；REQ-F-027 |
| 运营（含推广、运营、销售数据负责人） | 公司内维护数据来源与路由的人 | 控制台 operator | 维护智能体/Webhook 来源、绑定与汇总屏障；处理死信与告警 | 业务配置（不含成员与权限管理） | 场景 2；ADR-006（admin/operator/viewer） |
| 公司管理员 | 公司自建中转的运维者 | 公司组织 admin；中转主机管理员 | 部署公司中转（DEC-048）、管理成员与权限、保管 IM 凭据主密钥 | 公司中转上的一切配置 | DEC-047/048 |
| 订阅者（v2） | 场景 4 的资讯接收人（公司内部 + 少量订阅者） | 推送团队成员 | 订阅/退订 | 仅自身订阅 | DEC-046；BL-002/003 |

## 2. 开发与验证角色（AI Agent / CLI）
所有权路径以 `04_planning/ownership-matrix.md` 为唯一源；档位以 `04_planning/cost-budget.md` 为准（DEC-050）。

| 角色 | 职责 | 不得做 |
|---|---|---|
| 规划 Agent（opus 档） | 维护需求基线、ADR、架构、计划、本治理目录；仲裁跨模块冲突 | 写实现代码；替用户裁定 BLOCKING 未知项 |
| Agent-Guard | 脚手架、根白名单、Makefile/CI 守卫、安装部署脚本（TASK-001/014/209） | 改业务模块 |
| Agent-Contract | `packages/contracts/` 构建与生成（TASK-002）；冻结后改契约须新任务 + ADR | 与实现任务并行改契约 |
| Agent-Data | 迁移运行器、`database/migrations/`（只新增文件） | 改已合并迁移 |
| Agent-Relay | 云中转各模块 | 动渠道适配器目录、节点代码 |
| Agent-Node | 本机节点各模块、ACP 夹具 | 动中转代码（`audit/application/twin-forward` 除外） |
| Agent-App | `apps/web` 两个构建目标 | 直接访问后端内部模块 |
| Agent-Channel | 6 个 IM 适配器目录 | 在核心写渠道特判 |
| Agent-QA | testkit、E2E/集成测试、`06_validation/` | 修改被测实现代码 |
| Agent-Docs | `docs/**`（不含 evidence），TASK-211 文档同步 | 改上层事实（需求/ADR/范围）而不经裁定 |
| 独立验证者 | 按验收条目逐条复现任务结果，只输出 PASS / FAIL / UNKNOWN 及理由 | 参与被验任务的实现；修代码；给“基本通过”类模糊结论 |

## 3. 外部方
| 外部方 | 关系 | 影响 |
|---|---|---|
| IM 平台（腾讯微信 iLink / QQ 开放平台、飞书/Lark、钉钉、Telegram、Discord） | 渠道能力与限额提供方 | 限额、条款与接口变化直接影响渠道（`risks.md` R-01/R-06） |
| ACP 协议与各智能体维护方 | 输入端协议与可执行文件提供方 | 版本、preview 状态、启动参数（R-05/R-10） |
| 云主机/网络提供方（香港，暂定） | 中转运行环境 | 跨境连通（R-04） |

## 4. RACI（关键事项）
R=执行 A=最终负责 C=咨询 I=知会

| 事项 | 用户本人 | 规划 Agent | 实现 Agent | 独立验证者 | 朋友/公司 |
|---|---|---|---|---|---|
| 需求范围变更 | A | R | I | I | C |
| ADR / 契约变更 | A（可推翻） | R | C | I | I |
| 任务实现 | I | C | R | I | — |
| 任务验收结论 | I | A | C | R | — |
| 真机冒烟（扫码、手机） | R | A | C | C | R（P2 飞书） |
| 中转部署与运维 | R（个人中转） | C | C（TASK-209 脚本） | — | R（公司中转） |
| 风险登记更新 | I | R/A | C | C | I |
