# WorkFleet 大白话使用说明（v1 设计态）

> ⚠️ **产品还没写出来**（仓库目前没有任何业务代码，见 `08_knowledge/fact-baseline.md`）。本文按 V0.0.4 已冻结的设计写“做出来以后怎么用”。
> 标“（待真机）”的步骤依赖还没实测过的平台行为；标“（实验）”的功能可能不稳定。按钮名称、页面位置以最终界面为准。
> 本文在 V0.0.3 版使用说明的基础上更新：V0.0.3 时 IM 是必需的、只有微信和飞书；现在**网页控制台是默认入口**，6 个 IM 都是可选加装，所有主流 ACP 智能体都能接。

---

## 一、一句话
**打开一个网页（或者手机上任意一个你常用的聊天软件），就能同时指挥你电脑里的 Claude Code、Codex、Cursor、ZCode、OpenClaw 等所有工具；手机只扫一次码，以后换工具不用再“绑这个、解那个”。**

## 二、它由三块组成
1. **云中转**（一台云服务器，Ubuntu/Linux，暂定放香港）：替你挂着各个聊天机器人，24 小时收发消息；同时提供网页控制台。几个人可以共用一台、按账号隔开；公司可以自己部署一台（全部开源）。
2. **本机节点**（装在你自己的每台电脑上，Windows / Mac / Linux 都行）：负责启动和驱动你的开发工具。**代码、工具账号、模型 Key 永远留在你电脑上**，它主动连到云中转，家里不用开端口。
3. **入口**：
   - **网页控制台**（默认）：电脑浏览器或手机浏览器打开即可，手机上可以“添加到主屏幕”像 App 一样用，还能收推送。
   - **聊天软件**（可选）：微信 ClawBot、飞书/Lark、QQ、钉钉、Telegram、Discord，想用哪个接哪个，可以同时接好几个。

消息怎么走：**你 → 云中转 → 你的电脑 → 某个工具**；工具的回复原路回来。电脑关机时，中转会告诉你“设备离线，已排队”，开机后自动补发。

## 三、开始前你需要准备
- 一台云中转：自己部署（需要一个域名和 HTTPS 证书），或者让已经部署好的朋友/公司给你开账号。
- 你要用的开发工具，**先在电脑上装好并登录好**（WorkFleet 不替你登录它们的账号）。
- 可选：要接的聊天软件账号（比如你的微信）。

## 四、最简单的用法：只用网页（不接任何聊天软件）
1. 打开中转的网址，**注册账号**（会自动给你建一个“个人组织”）。
2. 在控制台“设备”页点 **“生成配对码”**，得到一个 **8 位数字**，10 分钟内有效。
3. 在你电脑上装好本机节点，运行 `workfleet-node pair`，把 8 位码填进去。几秒后控制台显示这台电脑 **“在线”**。
4. 在“智能体”页点“添加”，选工具（比如 Claude Code），选它要干活的**项目文件夹**，起个短名字（比如 `cc1`）。
5. 打开“对话”，选 `cc1`，直接打字聊。工具要删文件、跑高权限命令时，页面弹出审批卡，你点“同意”或“拒绝”。
6. 手机上：用浏览器打开同一个网址 → “添加到主屏幕” → 允许通知。以后审批、完成、失败、卡住都会推送到手机（iPhone 需要 iOS 16.4 以上且必须先添加到主屏幕，待真机）。

## 五、可选：加装聊天软件
在控制台“渠道”页添加即可，每种的准备工作不同：
| 聊天软件 | 你要做的 |
|---|---|
| 微信 ClawBot | 控制台点“绑定微信” → 手机微信扫码一次（详见第六节） |
| 飞书 / Lark | 在飞书开放平台建一个**专门给 WorkFleet 用的**企业自建应用，把凭据填进控制台；国内版 feishu.cn、国际版 larksuite.com 都支持 |
| QQ | 在 QQ 开放平台建官方机器人，把凭据填进来 |
| 钉钉 | 建企业内部应用（Stream 模式），凭据填进来 |
| Telegram | 找 @BotFather 建 Bot，把 token 填进来 |
| Discord | 在开发者后台建 Bot，把 token 填进来 |

**每个聊天软件接好后都要做一步“识别我的账号”**：在聊天里给机器人发 `/bind`，它会回一个 **6 位码**，你在控制台里确认这个码。没做这一步的人给机器人发消息，只会收到一句固定提示，指挥不了你的工具（防止别人乱发指令）。

## 六、★ 用微信同时管好几个 ZCode 和 Claude Code（分步操作）

> 场景：你电脑上开着 2 个 Claude Code、2 个 ZCode，分别在不同项目里干活，你只想用一个微信收发。
> 一句话原则：**扫码只在 WorkFleet 控制台扫一次；ZCode 和 Claude Code 里都不扫码。**

**第一步：准备（只做一次）**
1. 确认 Claude Code 和 ZCode 都已经在电脑上装好、登录好，能正常用。
2. **先关掉 ZCode 自带的“微信 Bot / 移动端远程控制”**（如果你以前开过）。原因：同一个微信授权只认最后扫码的那个程序，ZCode 和 WorkFleet 会互相把对方“顶掉”（待真机）。ZCode 自带的飞书机器人如果用的是另一个飞书应用，可以保留。
3. 按第四节 1–3 步：注册中转账号 → 生成 8 位配对码 → 电脑上运行 `workfleet-node pair` 配对，控制台显示“在线”。

**第二步：把 4 个工具登记进来（在控制台“智能体”页）**

4. 添加 Claude Code，选项目文件夹 A，起名 `cc1`。
5. 再添加一个 Claude Code，选项目文件夹 B，起名 `cc2`。
6. 添加 ZCode，选项目文件夹 C，起名 `z1`；再添加一个 ZCode 选项目文件夹 D，起名 `z2`。ZCode 走社区桥接（`zcode-acp-server`），**属于实验功能**，如果节点提示缺少桥接程序，按提示安装；接不上不影响其他工具。
7. 尽量**一个文件夹只放一个会写代码的工具**。如果两个工具指向同一个文件夹，WorkFleet 会拒绝第二个写入者，或自动给它开一个 git worktree，避免互相改坏。
8. （可选）先在网页“对话”里分别跟 `cc1`、`z1` 说句话，确认都能回。

**第三步：绑定微信（这是唯一一次扫码）**

9. **什么时候扫**：上面第 2 步（关掉 ZCode 自带微信 Bot）做完之后。
10. 手机微信里先确认 ClawBot 功能已经可用（平台前置条件，待真机）。
11. 控制台“渠道”页点 **“绑定微信”**，屏幕上出现二维码 → **用手机微信扫这个码**，在手机上确认授权。控制台显示“已连接”。
12. 在微信里给这个机器人发 **`/bind`**，它回你一个 6 位码 → 回到控制台“接收人”页确认这个码。从此这个微信就是“你本人”，可以指挥工具了。

**第四步：连线（告诉 WorkFleet 谁的消息发到哪）**

13. 在“绑定”页新建一条 **管理模式（多对一）**：来源勾选 `cc1`、`cc2`、`z1`、`z2`，目标选你的微信。
14. 点 **“预览（dry-run）”**，输入一句样例话，看它会被送到哪个工具——确认无误后保存。

**第五步：日常怎么用（全在微信里）**

15. 每条工具发来的消息前面都带标签，比如 `[项目A/cc1]`，一看就知道是谁说的。
16. 想给某个工具下命令：发 **`@cc1 修一下登录页`**；想给 ZCode 二号：**`@z2 跑一下测试`**。
17. 想接下来一直跟某个工具聊：发 **`/use z1`**，之后不带 @ 的话都发给 `z1`。
18. 想回某条消息：直接**引用那条消息回复**，回复只会回到产生它的那个工具和那个对话。
19. 工具要做危险操作时，微信里会收到“审批 #3：……”，回 **`Y3`** 同意、**`N3`** 拒绝；不回的话超时默认拒绝。
20. 常用指令：`/list` 看有哪些工具在线、在干嘛；`/status cc1` 看状态和排队；`/clear cc1` 给它开新对话（旧记录还在）；`/history` 查最近记录；`/stop z1` 停掉它当前这一轮；`/stop all` 一键全停（5 秒内生效，控制台可恢复）。

**第六步：以后什么时候需要再扫码**

21. **正常情况下不用再扫**。加新工具、换工具、开新对话都不用扫。
22. 只有当微信授权失效时才需要重新扫：WorkFleet 会立刻发 **p0 告警**（走网页推送或你配置的备用聊天软件），按提示回控制台“渠道”页重新扫一次即可。
23. 微信的限制要知道（待真机）：你 **24 小时没给机器人发过消息**，或者一次对话后机器人已经主动发了**约 10 条**，它可能就发不出新消息了。WorkFleet 会在剩余 ≤3 条时提醒你“回任意一个字续期”；发不出去的消息会排队，或改走网页推送。
24. 电脑关机/休眠时：消息会排队，你会收到“设备离线，已排队”，开机后自动补发。

## 七、朋友怎么用（飞书 + OpenClaw）
1. 在飞书开放平台建一个**属于 WorkFleet 自己的**企业自建应用，凭据填进控制台。
2. 他电脑上的 OpenClaw 通过 `openclaw acp` 接进本机节点（在“智能体”页添加 OpenClaw）。
3. OpenClaw 原来那个飞书机器人可以继续留着，但**不要和 WorkFleet 共用同一个飞书应用**——同一个应用连两个程序，飞书会把每条消息随机只发给其中一个（已确认）。
4. 只有经过 WorkFleet 转发的对话才会记录在 WorkFleet 里，界面上会注明。

## 八、四种模式（在控制台“绑定”页连线）
- **管理模式（多对一）**：很多工具 → 一个聊天。第六节就是这个。
- **通知模式（一对多）**：一个来源 → 多个接收人，比如日报同时发给“数据分析群”和“老板”。**接收人也能回话，而且每个人的回话各自是独立对话，不会混在一起。** 注意：微信不能拿来给别人群发（平台限制），群发请用飞书、钉钉、Telegram、Discord 等。
- **团队模式（多对多）**：按项目或产品线分流。比如产品线 A 的开发、推送、监控、报表全进微信，产品线 B 进 QQ，公司审批进飞书。一条消息只会到一个目标工具，**不会默认群发给所有工具**。
- **总控模式**：见第十节。

## 九、多台电脑、多个中转、多个项目
- **多台电脑**：每台都装本机节点、用同一个账号配对。可以设一台“主设备”（总控默认跑在这里）。`@别名` 会准确找到在哪台电脑上的哪个工具；那台电脑离线时消息排队并提示。
- **多个中转**：一台电脑可以同时连“个人中转”和“公司中转”。两边的路由、凭据、消息完全隔离，互相看不见。
- **项目**：先建项目，工具、对话、绑定都挂在项目下。可以有主项目和子项目（最多 3 层），控制台有一个汇总视图看所有子项目的未读、运行中、待审批。

## 十、总控（职业经理人）
1. 在**本机控制台**（只在你电脑上打开的 `127.0.0.1:5100`）配置模型：提供方、地址、Key、模型名、参数、**每日/每月费用上限**、超限后怎么办（默认降级为规则把关并通知你）、系统提示词。Key 只存在你电脑的系统钥匙串里，不会上传服务器。
2. 在绑定页选 **总控模式**。之后每个工具的每条输出都先给总控看：小事它直接回、合并成摘要，或丢弃并记理由；回不了的、重大决策、要花钱的才交给你。这一步**不能关**。
3. 随时找总控聊：发 **`/boss 现在进度怎样`**，不会打断正在干活的工具。
4. 开会：你提一个需求，总控组织几个工具“开会”，各自分析，总控出纪要、拍板、分派任务（也可能只派给一个）。
5. 需求已经拆好了：把符合任务卡格式的文件夹交给总控，它直接按依赖顺序分派，不用再开会拆。
6. 总控的 AGENTS.md 和 Skills 上传在第三版才有，第一版只有系统提示词。

## 十一、公司场景（老板 + 部门 + 运营）
- 公司建议**自己部署中转**（中转能看到聊天明文，见第十四节）。
- 角色：管理员（管成员与权限）、运营者（管工具、绑定、汇总）、只读（看）。
- 同一份汇总，老板和数据部可以看到不同的字段（按“接收人 × 业务线 × 字段”过滤和脱敏）。
- 每条发出去的消息都能查到：发给了谁、来自哪个工具、经过了哪些过滤。

## 十二、你的“分身数据”
你本人发出的所有指令、审批、纠正，以及任务时间线，会记在**你自己电脑上**。第一版只记录、不学习；你可以在本机控制台查看、修改、删除、导出（JSONL）。学习你的习惯是第四版以后的事。

## 十三、四个场景怎么配
| 场景 | 怎么配 | 第一版能不能用 |
|---|---|---|
| 1. 三个项目、六个工具、微信统一收 | 管理模式，6 个工具 → 1 个微信，按项目打标签；同文件夹写保护 | ✅ |
| 2. 飞书数据管理（推广/运营/销售 → 数据部 + 老板） | 团队或通知模式 + 汇总屏障（三个来源收齐或超时再发一条）+ 字段过滤；来源可以是智能体、Coze 或 Webhook | ✅ 汇总与权限；每天定时出报表要等第二版的定时任务（v1 只能由来源自己按时推） |
| 3. 主项目 + 子项目，总控统一开发 | 项目树 + 总控模式 + 导入任务清单 | ✅ |
| 4. 每天 9 点给订阅者推 AI 资讯 | 定时任务 + 通知模式 + 推送团队 | ❌ 第二版；微信不能给别人群发，公司外订阅者建议用 Telegram |

## 十四、目前做不到 / 要知道的风险
- 同一个微信不能同时给 WorkFleet 和别的工具用（平台限制，不是我们选的）。
- 电脑关机时，那台电脑上的工具没法干活，只能排队。
- 中转能看到消息明文（聊天平台推过来就是明文），共用中转的人要互相信任；公司请自建。
- 微信主动消息有 24 小时 / 约 10 条的限制（待真机）。
- ZCode 没有官方接口，靠社区桥接，属于实验；它的使用条款是否允许这样接入还没核实。
- GitHub Copilot CLI 的接入官方还是预览版。

## 十五、“用微信管多个 ZCode 和 Claude Code”到底能不能实现？（QA-26.5 的书面答复）
| 部分 | 判断 | 依据 |
|---|---|---|
| 多个 Claude Code | **能**：走 ACP Registry 收录的适配器（`@zed-industries/claude-agent-acp`），每个实例一个子进程，单节点设计目标 ≥8 个并发会话 | DEC-025/055；`input-adapters.v1.json`；REQ-NF-002（启动参数与并发待 TASK-022、TASK-210 实测） |
| 用一个微信统一收发 | **能，但有限额**：扫一次码、@别名分发、引用回复溯源都在设计内；主动消息受 24h/约 10 条限制，靠额度预算器与续期提示缓解 | DEC-034/038；R-01；U-02（待 TASK-041 真机） |
| 多个 ZCode | **大概率能，但属于实验**：没有官方 ACP，依赖社区桥或私有协议；多个实例同时运行是否稳定、条款是否允许，都还没验证 | V0.0.3 F-19；R-02；A-05（待 TASK-084） |
| 不在电脑前也能收到 | **能**：网页 PWA 推送或备用聊天软件 | DEC-057；R-12（iPhone 待实测） |
