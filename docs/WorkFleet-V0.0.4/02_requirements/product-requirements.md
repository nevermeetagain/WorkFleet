# 产品需求基线（v1）

## 1. 复述
一个开发者同时用 5 个以上编码工具，却只有一个常用微信，反复扫码换绑。WorkFleet 让他（以及他的老板、部门、订阅者）只在一个入口——Web 控制台或任一主流 IM——与任意多个本机智能体对话、审批、看记录；并可由“总控（职业经理人）”统一把关、开会、分派与汇报。

- 用户：开发者本人（P1：微信 + 本机 CLI）、朋友（P2：飞书 + 外部智能体）、公司成员（老板、部门、运营）。
- 管理端：中转控制台的 admin/operator/viewer；本机控制台只给设备所有者。
- 系统边界：智能体在用户电脑；IM 与账号在中转；模型只在本机。

## 2. 功能需求（MUST/SHOULD/COULD）
| ID | 需求 | 级别 | 可验证陈述 | 切片 |
|---|---|---|---|---|
| REQ-F-001 | 本机节点 | MUST | 在 Windows 11、macOS 14、Ubuntu 24.04 上，`workfleet-node` 安装后可开机自启、单实例运行，并在中转控制台显示“在线”。 | S0,S10 |
| REQ-F-002 | 云中转与多租户 | MUST | 两个不同组织的用户在同一中转上互相看不到对方的任何项目、渠道、消息与审计记录（跨组织请求一律返回 404 `NOT_FOUND`（不泄露存在性，ADR-015 #24））。 | S0,S7 |
| REQ-F-003 | 账号、组织与角色 | MUST | admin/operator/viewer 三角色的权限矩阵与 `contracts/identity/permissions.json` 一致，并由契约测试逐格验证。 | S0,S7 |
| REQ-F-004 | 项目一级对象与主/子项目 | MUST | 用户可建主项目与子项目（深度 ≤3），会话、绑定与智能体都必须归属一个项目，跨项目视图可按树汇总未读与状态。 | S3 |
| REQ-F-005 | 一个账号多台设备 | MUST | 同一账号登记 ≥2 台节点时，可按设备路由（`@别名` 唯一定位到设备上的智能体），目标设备离线时消息排队并提示。 | S3 |
| REQ-F-006 | 多中转连接 | MUST | 一个节点可同时登录 ≥2 个中转，两边的路由、凭据、消息互不可见（隔离测试通过）。 | S3 |
| REQ-F-007 | 通用 ACP 输入 | MUST | 按 `InputAdapterSpec` 表接入 ACP 智能体；DEC-055 实测清单中每一个都有通过的录制回放夹具与一次真机冒烟记录（实验项允许标注失败原因）。 | S1,S4 |
| REQ-F-008 | 非 ACP 输入：Coze 与 Webhook | MUST | Coze（HTTP API）可作为输入端对话；`POST 127.0.0.1:5102/hooks/{hookId}`（签名校验）的消息按绑定投递到输出端。 | S4 |
| REQ-F-009 | 输出端：微信 ClawBot | MUST | 控制台扫码一次完成绑定；授权失效时 p0 告警；主动消息受额度预算器约束并在剩余 ≤3 条时提示续期。 | S2 |
| REQ-F-010 | 输出端：飞书/Lark | MUST | 同一适配器按配置连接 feishu.cn 或 larksuite.com，长连接收消息、卡片按钮审批、卡片流式更新。 | S5 |
| REQ-F-011 | 输出端：QQ 官方机器人 | MUST | 单聊与群聊收发；主动消息受平台配额约束并按能力降级。 | S6 |
| REQ-F-012 | 输出端：钉钉 | MUST | Stream 模式收消息，单聊/群聊发送，互动卡片审批。 | S6 |
| REQ-F-013 | 输出端：Telegram | MUST | getUpdates 长轮询收发，内联按钮审批，支持频道群发（通知模式）。 | S6 |
| REQ-F-014 | 输出端：Discord | MUST | Gateway 收发，按钮组件审批，频道消息。 | S6 |
| REQ-F-015 | Web 控制台对话（默认渠道） | MUST | 不配置任何 IM 时，用户可在 Web 完成：注册→配对节点→与智能体对话→审批→查历史；PWA 安装后能收到 Web Push。 | S0,S1,S10 |
| REQ-F-016 | 绑定与三种模式 | MUST | 管理（多对一）、通知（一对多）、团队（多对多）三种绑定均可在控制台创建，并有 dry-run 预览显示一条样例消息会去哪；团队模式入站只到一个目标。 | S2,S5 |
| REQ-F-017 | 回复溯源与按发送人分会话 | MUST | 在 IM 中引用某条消息回复，回复只到产生该消息的智能体会话；通知模式下两个接收人的回话进入两个独立会话。 | S2,S5 |
| REQ-F-018 | IM 与控制台指令 | MUST | `/clear /list /use /@别名 /stop /stop all /status /history /bind /help` 在所有渠道与 Web 行为一致（以 `contracts/commands/im-commands.json` 为准）。 | S1,S2 |
| REQ-F-019 | 会话与记录查询 | MUST | `/clear` 后 generation+1 且旧记录仍可查；按会话 display_id 或原生 resume_id 可查到两端（IM 侧与智能体侧）记录。 | S1 |
| REQ-F-020 | 审批与 held | MUST | 智能体权限请求在 IM/Web 以按钮或 `Y{n}/N{n}` 审批；超时默认拒绝；待审批期间发往该智能体的新消息进入 held，审批后按序投递。 | S2 |
| REQ-F-021 | 汇总屏障 | MUST | 配置 N 个来源的汇总任务，在全部提交或超时后只发出一条汇总；超时时标注缺失来源。 | S5 |
| REQ-F-022 | 总控：把关分级 | MUST | 总控模式下每条智能体输出都经总控分级为 直回/合并/上报/丢弃 之一并记录理由；不可关闭。 | S8 |
| REQ-F-023 | 总控：随时对话与任务分派 | MUST | 用户与总控对话时，正在执行的任务不暂停、不丢消息；总控可把任务分派给 1..N 个智能体。 | S8 |
| REQ-F-024 | 总控：会议 | MUST | 总控可组织 ≥2 个智能体开会：轮次、发言、纪要、决策四类事件可回放；主持策略“全员提交或超时”。 | S9 |
| REQ-F-025 | 总控：导入任务清单 | MUST | 总控可读取指定目录下符合 `task-template.md` 格式的任务卡并直接分派，跳过会议拆解。 | S9 |
| REQ-F-026 | 模型配置与费用上限 | MUST | 用户可增删改模型配置（含日/月费用上限与超限动作）；Key 仅存在节点钥匙串（中转数据库与日志中 grep 不到）；超限后总控降级为规则把关并通知。 | S8 |
| REQ-F-027 | 接收人级权限与脱敏 | MUST | 同一条汇总发给老板与数据部时，按“接收人 × 业务线 × 字段”规则得到不同的可见字段；脱敏规则有单测。 | S7 |
| REQ-F-028 | 审计 | MUST | 每条出站消息可查：发给谁、来自哪个输入端、经过哪些过滤；管理操作（改绑定、改权限、吊销设备）全部入审计。 | S7 |
| REQ-F-029 | 分身数据采集 | MUST | 用户本人发出的全部指令与任务时间线写入节点 `twin_event`；用户可在本机控制台查看/修改/删除/导出（JSONL）。 | S7 |
| REQ-F-030 | 通知分级与渠道健康 | MUST | p0–p3 四级；凭据失效、额度将尽、长连接断开在 60 秒内产生 p0 告警并走备用渠道。 | S6 |
| REQ-F-031 | Bot 唯一消费者与画像向导 | MUST | 向导按画像 P1/P2 生成默认配置；检测到同一 Bot 身份被他处消费（消息丢失/被顶掉）时告警。 | S10 |
| REQ-F-032 | 同目录并发写保护 | MUST | 同一工作目录同一时刻只允许一个写入型智能体持有租约；第二个写入请求被拒或自动分配 git worktree。 | S3 |
| REQ-F-033 | 急停 | MUST | `/stop all` 在 5 秒内停止该组织所有智能体的下发与出站（进程退出可晚于 5 秒）；控制台可恢复。 | S10 |
| REQ-F-034 | 配置导入导出与 doctor | SHOULD | 业务配置可导出/导入 YAML（不含密钥）；`workfleet doctor` 检查端口、钥匙串、中转连通、智能体可执行文件。 | S10 |
| REQ-F-035 | 恢复密钥与换机 | SHOULD | 导出恢复密钥后，在新电脑导入可恢复节点的加密数据。 | S10 |
| REQ-F-036 | 异常阈值 | COULD | 在绑定上配置指标阈值，越线升为 p0。 | backlog→v2 |

## 3. 非功能需求
| ID | 维度 | 可验证陈述 |
|---|---|---|
| REQ-NF-001 | 响应时延 | 入站到回执 p95 ≤ 3 s（渠道支持回执时）；Web 发送到节点收到 p95 ≤ 1 s（同城）/ ≤ 2 s（跨境，部分确认）。 |
| REQ-NF-002 | 并发与资源 | 单节点 ≥ 8 个并发智能体会话；空闲会话 15 分钟回收；节点控制面常驻内存 ≤ 200 MB（不含子进程）。 |
| REQ-NF-003 | 可靠性 | 所有跨进程消息至少一次投递 + 幂等键去重；中转重启或断线 10 分钟内恢复后不丢消息、不重复外发。 |
| REQ-NF-004 | 安全 | 中转只开 443；节点端口只绑 127.0.0.1；IM 发送者默认未授权；入站文本按不可信处理；模型 Key 不出节点；gitleaks 门禁。 |
| REQ-NF-005 | 隐私与数据主权 | 控制台明示“中转可见 IM 明文”；分身数据只在节点；支持导出与删除。 |
| REQ-NF-006 | 可移植 | 三平台安装/运行/测试矩阵通过；GBK 控制台输出、CRLF、长路径（>260）在 Windows 用例中覆盖。 |
| REQ-NF-007 | 可观测 | 所有日志带 trace_id 贯穿 web→relay→node→agent；/metrics（Prometheus 文本）；死信可在控制台查看与重放。 |
| REQ-NF-008 | 可扩展 | 新增一个 IM = 新增一个 channel 适配器目录 + 注册一行，核心零改动；新增一个 ACP 智能体 = 一条 spec + 一个夹具。 |
| REQ-NF-009 | 可测试 | CI 不依赖真实 IM 与智能体（FakeAgent/FakeChannel）；契约测试由 schema 生成。 |
| REQ-NF-010 | 成本 | 总控每日/每月费用硬上限可配，超限动作默认降级为规则把关。 |
| REQ-NF-011 | 可用性与语言 | Web 首屏（中转控制台）在 4G 网络下可交互 ≤ 3 s；界面 zh-CN 为主，文案集中在 i18n 资源。 |

## 5. MUST NOT（明确不做）
1. 中转运行模型或保存模型 Key（DEC-044）
2. 由 LLM 决定消息发往哪个渠道（DEC-005）
3. 团队模式默认广播（DEC-006）
4. 用微信 ClawBot 向他人群发（DEC-046）
5. 代码或工作目录内容上传中转（DEC-037）；仅允许用户主动发送的消息/摘要
6. 拷贝 AGPL/EULA 项目代码（DEC-009）
7. 与其他程序共用同一 Bot 身份（DEC-034）
8. v1 实现分身学习 loop、知识库、定时任务、推送团队、AGENTS.md/Skills 上传（路线图 v2–v4）

## 8. 隐含要求与前置条件
- 必须有“配对码”让节点认领到账号（用户没说但必需）。
- 必须有“识别我的账号”步骤，否则任何加了 Bot 的人都能指挥智能体。
- 中转需要域名与 TLS 证书（部署前置）。
- 每个外部智能体需已在本机安装并登录（WorkFleet 不代为登录其账号）。
- 微信 ClawBot 需用户先在微信内启用 ClawBot 能力（平台前置，部分确认）。
