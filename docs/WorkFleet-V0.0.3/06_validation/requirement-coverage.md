## 4. 场景代入
### 场景 1：三个项目、六个工具，微信统一收
- 走法：手机微信 → 中转 → 本机节点 → 6 个工具会话，按项目标签回传。
- 🟡 六个工具：v1 有 Claude Code、Codex、Cursor、OpenClaw、ZCode（实验）共 5 个；Coze 在 v2（DEC-052）。第 6 个取决于你实际用什么。
- 🟡 同一项目多工具同时写：G10 并发写保护（同目录只允许一个写入型 Agent 或强制 worktree）当前是 SHOULD → 升为 v1 MUST（DEC-053）。
- ❌→已补 “项目”是一级对象：会话、绑定、标签都挂在项目下 → **新增 G23**。

### 场景 2：飞书数据管理，推广/运营/销售三个分析源 → 数据部 + 老板
- 🟡 分析源可能不是编码 CLI：用 Webhook/HTTP 输入或 OpenClaw/Coze 承接（DEC-052）。
- ❌→已修 老板要的是三方汇总：G1 汇总屏障原在 v2，场景 2 已确认真实使用（DEC-047）→ 移入 v1（DEC-053）。
- ✅ 按人看数据、脱敏、审计：v1（DEC-047）。
- 🟡 若是“每天/每周报表”，依赖定时任务（v2）；v1 只能由来源自己按时推送。

### 场景 3：主项目 + 子项目，账号通用，一个管理入口，总控统一开发
- ✅ 一个账号、一个控制台入口。
- ❌→已补 项目层级（主/子项目）与跨项目视图 → 并入 **G23**。
- ❌→已补 你“需求已分解完毕”：总控要能导入现成的需求/任务清单（如仓库里的 md 任务卡）直接分派，而不是重新开会拆 → **新增 G24**。

### 场景 4：每天 9 点给订阅者推 AI 资讯
- ✅ 定时任务 + 通知模式 + 推送团队（v2，DEC-046）。
- ❌ 微信 ClawBot 不能给他人群发（已确认）。
- 🟡 订阅者在公司外：飞书机器人能否主动触达租户外用户 `证据不足`；公司外的订阅者更适合 Telegram（v2）或钉钉/飞书外部群 → 记入 U-03 待验证。
