# 05 · 需求增补

> 来源：2026-10-17 飞书“公司各业务汇总给领导”场景推演、18 维分析与 V0.0.2 复核。优先级为建议值，Q-12 裁定后可能调整。

| 编号 | 需求 | 触发场景 | 建议级别 | 借鉴 |
|---|---|---|---|---|
| G1 | 汇总屏障：汇总任务等待 N 个来源全部提交或超时；超时时标注缺失来源后照常发出 | 每日汇报 | MUST | BF 收齐判定、OR task deps |
| G2 | 回复溯源路由：IM 中回复/引用某条消息时，回到产生该消息的 Agent 与会话，并只回给提问人 | 领导追问 | MUST | PC chat message links |
| G3 | 接收人级权限：按“接收人 × 业务线 × 字段”过滤与脱敏；接收人级静默时段（只放行 p0） | 按人隔离、免打扰 | SHOULD（Q-12 选 A 则 MUST） | PA 脱敏 |
| G4 | 多级汇总：业务线 → 事业部 → 公司 | 新增业务线 | COULD | — |
| G5 | 飞书多维表格/报表作为原生输入源 | 数据在飞书里 | COULD | — |
| G6 | 异常阈值配置：在绑定或输入端上配置指标阈值，越线升为 p0 即时推送 | 异常上报 | SHOULD | — |
| G7 | 渠道健康告警：凭据过期、额度将尽、长连接断开，走备用渠道 | 全部 | MUST | WCB expired |
| G8 | 提示注入防护：IM 入站文本带来源标记、不可信内容不进系统提示、高危工具调用必须审批 | 全部 | MUST | — |
| G9 | 一键急停：`/stop all` 冻结所有 Agent 与出站，控制台可恢复 | 全部 | MUST | dsh-channels `/stop` |
| G10 | 同一工作目录并发写保护：同一仓库目录同一时刻只允许一个写入型 Agent，或强制 worktree | S1 多工具同项目 | SHOULD | OR worktree |
| G11 | 恢复密钥导出与换机恢复 | 备份 | SHOULD | — |
| G12 | Windows 原生运行要求：`.cmd` 启动、进程树清理、GBK/CRLF、长路径、休眠后长轮询补偿 | 部署 | MUST（Q-04 选 A 时） | — |
| G13 | 画像预设：P1“微信 + 本机开发 CLI”、P2“飞书 + 外部智能体（OpenClaw 等）”，安装向导按画像生成默认渠道、输入端与路由 | 用户与朋友两类场景 | MUST | DEC-035 |
| G14 | Bot 身份唯一消费者：同一飞书应用 / 微信授权只允许一个 WorkFleet 渠道实例绑定；向导明确提示“不要与 OpenClaw 等共用同一飞书应用”；检测到消息丢失或被顶掉时告警 | 入口冲突 | MUST | DEC-034 |
| G15 | 外部网关型智能体接入：以 ACP 桥（`openclaw acp`）作输入端；不接管其原生渠道；历史只记录经 WorkFleet 转发的部分并在界面注明 | P2 | MUST | F-16 |
| G16 | 飞书渠道同时支持 feishu.cn（国内）与 larksuite.com（国际 Lark）两套域名，按应用配置选择 | DEC-040（中转在香港，海外用户可能用 Lark） | 推断 |
