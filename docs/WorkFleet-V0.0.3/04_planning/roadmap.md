# WorkFleet 产品路线图

> 规则（DEC-045）：第二版及以后每个产品版本要加、要改的功能都记在本文件；每个文档版本（docs/WorkFleet-V0.0.x/）延续并更新本文件，变更写入文末“变更记录”，旧条目不删，改标 moved / cancelled。
> 产品版本（第一版 v1、第二版 v2……）与文档版本（V0.0.x）是两套编号。
> 来源标注：**【用户】**= 用户明确要求；**【规划】**= 规划者建议，可调整；**【待定】**= 依赖未裁定问题。

## v1 第一版（MVP）
| 功能 | 来源 | 依据 |
|---|---|---|
| 本机节点：Windows / macOS / Linux 一等支持 | 【用户】 | DEC-041 |
| 云中转：Ubuntu/Linux，暂定部署香港，多账号隔离，不运行模型、不存模型 Key | 【用户】 | DEC-037/039/040/044 |
| 输出端：微信 ClawBot、飞书（含 Lark 国际版） | 【用户】 | DEC-035、G16 |
| 输入端：Claude Code、Codex、Cursor（ACP）；OpenClaw（`openclaw acp`）；ZCode（实验） | 【用户】+【规划】 | DEC-035/038、G15 |
| 四种模式：管理（多对一）、通知（一对多）、团队（多对多）、总控 | 【用户】 | 原始说明书、DEC-043 |
| 总控：先把关分级，再会议；随时可对话不打断任务；自定义模型 | 【用户】 | DEC-043 |
| 模型配置：用户自建自管；请求参数、日/月费用上限与超限动作、系统提示词 | 【用户】 | DEC-044、G17 |
| 接收人级权限、脱敏、审计；控制台多用户与角色（管理员 / 运营者 / 只读） | 【用户】 | DEC-047、G3 |
| Bot 身份唯一消费者检查与冲突告警；画像预设 P1/P2 | 【规划】 | DEC-034、G13/G14 |
| IM 指令：`/clear` 新开对话、`/list`、`/use`、`/stop`；危险操作确认 | 【用户】`/clear` +【规划】其余 | 原始说明书 |
| 分身数据采集：全部用户指令 + 时间线（与审计日志共用，先只采不学） | 【用户】范围 +【规划】版本 | DEC-049、G21 |
| 多中转连接（个人 + 公司） | 【规划】 | DEC-048、G20 |
| Webhook/HTTP 通用输入（推送、监控、报表、数据分析来源） | 【规划】 | DEC-052 |
| 项目一级对象 + 主/子项目层级；一个账号多台设备 | 【规划】 | G22、G23 |
| 全部主流输出端：微信、飞书/Lark、QQ、钉钉、Telegram、Discord（取代 v2 的“更多输出端”） | 【规划】 | DEC-054 |
| 全部主流 ACP 智能体（通用适配器 + 官方 Registry）+ Coze | 【规划】 | DEC-055 |
| Web 控制台对话（云端即 ACP 客户端） | 【规划】 | DEC-056 |
| 云端控制台为默认渠道：不接 IM 也能完整使用；PWA + 浏览器推送通知 | 【规划】 | DEC-057 |
| 汇总屏障、回复溯源路由、同目录并发写保护 | 【规划】 | DEC-053、G1/G2/G10 |
| 总控导入现成任务清单直接分派 | 【规划】 | G24 |
| 通知模式回话按发送人分会话 | 【规划】 | G25 |
| 按会话 ID 查两端对话记录 | 【规划】（原为拓展项，因成本低提前） | 原始说明书 |
