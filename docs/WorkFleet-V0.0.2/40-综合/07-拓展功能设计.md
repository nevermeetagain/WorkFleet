## 1. 定时任务（“和手机闹钟大体一致”）

### 1.1 规则类型（继承）
| 原文 | `rule_json.type` | 示例 | 现有项目 |
|---|---|---|---|
| 只运行一次（A-13：“只运营一次”为笔误） | `once` | `{type:"once", at:"2026-10-20T09:00"}` | CCC timer、OCL at、AION At；Orca/Paperclip 无 |
| 每日 | `daily` | `{time:"09:00"}` | 全部 |
| 每周 | `weekly` | `{days:[1,3,5], time:"09:00"}` | 全部 |
| 每月 | `monthly` | `{day:15 \| "last" \| {nth:2,weekday:1}, overflow:"skip"\|"clamp"}` | cron 可表达日号 |
| 工作日 | `workday` | 中国法定工作日 = 周一至五非放假日 + **调休上班日** | **无人实现** |
| 休息日 | `restday` | 周六日非调休上班日 + 法定放假日 | **无人实现** |
| 高级 | `cron` | 5 段 cron + `calendar_filter` | 全部 |
闹钟式附加：`skip_next`、`until`、`count`、`paused_until`、一天多次 `times[]`。

### 1.2 节假日数据与缺年降级（复核后更新）
- 数据源 holiday-cn（MIT）每年 JSON（`date/name/isOffDay`；`isOffDay:false` = 调休上班）。
- **现状（2026-10-17）**：2027 年数据为空 → `holiday_year_status(CN,2027)=missing`；凡 2027 年的 `workday/restday` 触发点：
  1. 退化为周一至五/周六日并置 `schedule.calendar_degraded=1`；
  2. 控制台与 owner IM 提示“2027 节假日未发布，按周一至五计算”（K-32：100% 触发降级告警）；
  3. 数据到达后**重算所有受影响 `next_run_at`**，对已排入未触发的计划做差异提示。
- 手工覆盖 `source='manual'` 优先于公开数据（公司自定假期）。
- holiday-cn 停更 → 手工年表（每年约 30 条，国务院公告录入）。

### 1.3 判定与下次触发（继承 V0.0.1 §1.3–§1.4，伪代码不变）
`is_workday(d) = rec ? !rec.is_off_day : isoweekday(d) ≤ 5`；`next_fire` 按日迭代（horizon 800 天），支持多时刻与时区（订阅者可在他区，处理不存在/重复时刻）。

### 1.4 调度循环（继承 + 持久化队列原则）
- Tick 15s；乐观抢占 `UPDATE schedule SET next_run_at=? WHERE id=? AND next_run_at=?`；`schedule_run(schedule_id, planned_at)` 唯一键防重。
- catch-up：`skip | run_once | run_all_capped`（Paperclip routines）；宽限 10 分钟，超出记 `missed`（Orca `missedBeyondGrace`）。
- 并发：`skip_if_running | queue | parallel`。
- 动作：`prompt_agent`（`session_mode: reuse|new_per_run`）、`send_text`、`broadcast`、`sv_task`、**`content_collect`、`digest_compose`（新增，S4）**。
- 无人值守审批默认 `deny-unattended`。
- K-31：触发误差 ≤60s；30 天预览与实际逐条一致。

### 1.5 IM 中创建（自然语言 → 规则，回显确认）
`/remind 工作日 18:00 让 codex-a 汇总今日提交` → 解析（规则优先、模型兜底）→ 回显“下次触发：<日期> 18:00（Asia/Shanghai）；法定假日不触发，调休上班的周末会触发；2027 年起按周一至五（数据未发布）” → 用户“确认”才保存。

## 4. 分身数据 loop（R-506，A-16：用户本人数字分身）

### 4.1 管线（继承 V0.0.1 §4.2，增量）
```
采集（Gateway 事件：指令/需求原文、审批与驳回、对汇报的纠正、/clear 前会话总结、会议中被采纳/否决的意见）
  → 过滤（去心跳/进度/工具噪声/密钥；Memory Defense REDACT）
  → Hindsight persona:<owner> bank：retain(document_id=fleet_session_id, tags=[kind,project])
  → consolidation → observations
  → mental models（技术偏好、审批口径、沟通风格、汇报格式）
       触发器：delta + refresh_after_consolidation=true（增量）
             + full_refresh_cron="0 3 * * 1"（每周一 03:00 Asia/Shanghai 全量纠偏）【V0.0.2】
  → persona_revision(pending, diff) → p3 提示/控制台 → 用户批准 → 注入经理提示 / 员工任务包约定
  → 拒绝条目回写为“纠正”信号
```
- **为什么加全量**：Hindsight 自身路线把“增量与全量并存”作为长期主题（delta MM → `full_refresh_cron` #5674），增量长期运行会累积偏差（`15 §10`）。`refresh_cron` 与 `full_refresh_cron` 互斥，取后者。
- **降级**：无 Hindsight → AFX `core/memory.py`（`record_decision/record_correction/distill_from_report`）作采集钩子与简版画像。

### 4.2 隐私与成本
- 默认只采 owner 本人；群聊/他人消息默认不入库；可一键导出/删除（R-915）。
- retain 每条调 LLM：按事件类型过滤 + 每日批量；预算超限停采并提示；Hindsight 决策模型（默认关）可在 V0.6 评估降本。

## 6. 新增：配置版本化 / dry-run / 回滚（R-111、R-112、R-921）
- 每次保存绑定/输入端/输出端/日程/总控/订阅/内容源 → `config_revision(snapshot, diff, dry_run, actor)`。
- **dry-run**：用最近 N 条真实事件回放新路由，展示“这条消息会发给谁”（含被能力位拦截的项，K-35）。
- 热更新：编译索引原子替换，进行中会话 PID 不变（K-10 ≤5s）。
- `/config rollback <rev>`（owner）与控制台一键回滚；全部写 `audit_log`（K-46）。
- 与 `fleet.toml [gateway]` 双向导入/导出（GitOps）。

## 7. 新增：静默时段（R-913 可选）
- 用户配置 quiet hours（如 23:00–08:00 Asia/Shanghai）：p1–p3 进入 `held(quiet_hours)`，到点合并为一条“夜间摘要”；**p0 例外**。

## 8. 新增：Fleet-IR 汇报（总控纪要 / S2 日报 / S4 资讯）
- IR 子集：`heading / paragraph / list / table / callout / kpi / link / quote`，`ir_version` 字段；校验（结构、引用、空段）失败 → 修复 1 次 → 降级纯文本。
- 渲染器：飞书卡片 2.0、钉钉卡片、Telegram MarkdownV2、Discord embed、微信纯文本（≤N 字 + `/digest` 查看全文）、HTML 附件（控制台）。
- 来源：BettaFish ReportEngine 多阶段（模板→布局→篇幅→章节→IR 校验→渲染）与 SSE 补发模式（`agent.py:405-776`、`flask_interface.py:750-868`），**clean-room**；只取“小而稳的 IR 子集”教训（其 IR v1→v3 反复修补，`16 §7`）。
