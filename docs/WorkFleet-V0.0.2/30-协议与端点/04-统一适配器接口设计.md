# 04 · 统一适配器接口设计（InputAdapter / OutputAdapter / 消息信封 / 能力位）

> 【V0.0.2更新】本文件为 TS 初稿；V0.0.2 的 Python 落地、ACP 长期契约与新增表见 `40-综合/05-自研架构设计.md`。端口以 3100–3200 为准（本文 3000/3333 暂定已被取代）。

> 撰写日期：2026-10-16（Asia/Shanghai）。本文件是**设计稿**，所有外部 API 行为以 01–03 中带来源的事实为准；本文新增的均为 WorkFleet 自定义接口，不是任何平台的 API。
> 目标：高性能、高扩展；一个网关进程即可承载"多 Agent × 多 IM 账号"，并支撑管理/通知/团队/总控四种模式。

---

## 0. 设计原则（由 01–03 的硬约束推出）

| # | 原则 | 推导依据 |
|---|---|---|
| P1 | **网关是唯一事实来源**：所有入/出消息在网关落库（事件溯源），Agent 本地历史只做冷导入 | Claude 官方声明 JSONL 为内部格式勿解析；OpenClaw 回放有预算；Cursor 历史位置未知（02） |
| P2 | **按协议族抽象**输入端：`acp` / `stdio-custom` / `http-cloud` / `cli-oneshot` | 6 个输入端分属 3 类协议（02 §0） |
| P3 | **能力位驱动**，不按产品名写 if-else；未确认的能力默认关闭 | 大量 `证据不足` 项（02 §7、03 §11） |
| P4 | **Edge 优先**：网关跑在用户设备上；所有渠道用长连接/长轮询；Hub（云中继）可选 | Agent 只能本机 stdio（01 §3）；6 个渠道均有免公网模式（03 §0） |
| P5 | **出站必须经过配额/限流器与降级链** | 微信 24h/~10 条、飞书 5 QPS、Telegram 30/s 等（03） |
| P6 | **审批是一等公民**：ACP `session/request_permission` ↔ IM 交互（卡片按钮/回复指令） | 不回复会阻塞 Agent（01 §5、Cursor 文档） |
| P7 | **斜杠命令由网关拦截优先**（`/clear` `/use` `/list` …），未识别再透传给 Agent | ACP 无 /clear 原语（01 C5）；QQ/微信侧对斜杠命令支持各异 |

## 1. 总体架构

```
┌──────────────────────────── WorkFleet Edge（用户设备） ────────────────────────────┐
│                                                                                        │
│  InputAdapters (协议族)          Core                          OutputAdapters (渠道)   │
│  ┌──────────────┐        ┌─────────────────────────┐        ┌──────────────────┐      │
│  │ acp:claude   │◀──────▶│ SessionManager (映射/锁) │        │ wechat-ilink(长轮询)│◀──▶ 微信
│  │ acp:codex    │        │ Router (模式/绑定规则)   │◀──────▶│ feishu (WS长连接) │◀──▶ 飞书
│  │ acp:cursor   │        │ CommandBus (/clear 等)   │        │ qq (WS/Webhook)   │◀──▶ QQ
│  │ acp:openclaw │        │ PermissionBroker         │        │ dingtalk (Stream) │◀──▶ 钉钉
│  │ stdio:zcode  │        │ Renderer (降级链)        │        │ discord (Gateway) │◀──▶ Discord
│  │ http:coze    │        │ Outbox + RateLimiter     │        │ telegram(getUpdates)│◀──▶ TG
│  │ cli:oneshot  │        │ EventStore (SQLite/WAL)  │        └──────────────────┘      │
│  └──────────────┘        │ Scheduler (cron/工作日)  │                                   │
│        ▲                 │ Supervisor(总控, 可选)   │                                   │
│        │ spawn/stdio     └─────────────────────────┘                                   │
│  本机 Agent 进程池                     │ Admin API / Web UI（端口见 §11）               │
└────────────────────────────────────────┼───────────────────────────────────────────────┘
                                         │ 可选：WSS 隧道
                               ┌─────────▼─────────┐
                               │ WorkFleet Hub   │ 仅用于：需要 HTTPS 回调的渠道、多设备汇聚、
                               │ （云中继，可选）   │ 大规模广播（通知模式）
                               └───────────────────┘
```

- **两端直连**（管理/团队模式）= Edge 单进程即可。
- **总控模式**必须在 Edge（需求原文"总控模型必须运行在设备上"）。
- **通知模式**的大规模广播（场景 4）建议放 Hub：与个人设备解耦、可水平扩展；Edge 也能跑小规模。

## 2. 统一消息信封 `FleetEnvelope`（JSON Schema 摘要）

所有进入 Core 的东西（Agent 事件、IM 入站、定时触发、总控指令）都先转成信封；Core 内部只处理信封。

```jsonc
{
  "$id": "https://workfleet.local/schema/envelope/v1",
  "type": "object",
  "required": ["v", "id", "ts", "dir", "kind", "src", "conv"],
  "properties": {
    "v":    { "const": 1 },                                   // 信封版本
    "id":   { "type": "string", "description": "ULID，全局唯一、时间有序" },
    "ts":   { "type": "string", "format": "date-time" },      // 一律 UTC 存储，展示按订阅者时区
    "dir":  { "enum": ["in", "out"] },                        // 相对网关：in=进入网关，out=离开网关
    "kind": { "enum": [
      "msg.text", "msg.delta", "msg.final",                   // 文本：增量/最终
      "thought.delta",                                        // 思考流（默认不外发）
      "tool.start", "tool.update", "tool.end",                // 工具调用
      "plan.update", "usage.update", "session.info",
      "perm.request", "perm.decision",                        // 审批往返
      "cmd",                                                  // 斜杠/控制命令
      "turn.end", "error", "notice",
      "schedule.fire", "broadcast"
    ]},
    "src":  { "$ref": "#/$defs/endpointRef" },                // 来源端点
    "dst":  { "type": "array", "items": { "$ref": "#/$defs/endpointRef" } }, // 由 Router 填充
    "conv": {                                                 // 会话三元映射
      "type": "object",
      "required": ["fleetSessionId"],
      "properties": {
        "fleetSessionId": { "type": "string" },               // 网关自有会话 ID
        "agentSessionId": { "type": ["string","null"] },      // ACP sessionId / Codex thread_id / Coze conversation_id / ZCode session
        "channelThreadId":{ "type": ["string","null"] },      // 飞书 chat_id+thread / QQ openid / 微信 to_user_id / TG chat_id
        "turnId":         { "type": ["string","null"] }
      }
    },
    "parts": {                                                // 内容块（对齐 ACP ContentBlock）
      "type": "array",
      "items": { "oneOf": [
        { "properties": { "type": {"const":"text"}, "text": {"type":"string"}, "format": {"enum":["plain","markdown"]} } },
        { "properties": { "type": {"const":"image"}, "uri": {"type":"string"}, "mime": {"type":"string"} } },
        { "properties": { "type": {"const":"file"},  "uri": {"type":"string"}, "name": {"type":"string"}, "size": {"type":"integer"} } },
        { "properties": { "type": {"const":"diff"},  "path": {"type":"string"}, "unified": {"type":"string"} } },
        { "properties": { "type": {"const":"card"},  "cardRef": {"type":"string"}, "fallbackText": {"type":"string"} } }
      ]}
    },
    "actions": {                                              // 可交互动作（按钮/快捷回复）
      "type": "array",
      "items": { "properties": {
        "id": {"type":"string"}, "label": {"type":"string"},
        "kind": {"enum":["allow_once","allow_always","reject_once","reject_always","custom"]},
        "replyToken": {"type":"string", "description": "无按钮渠道的回复口令，如 'Y1'"}
      }}
    },
    "perm": { "$ref": "#/$defs/permissionPayload" },
    "prio": { "enum": ["p0","p1","p2","p3"], "default": "p2" }, // p0=告警/审批，p3=资讯
    "ttlMs":{ "type": "integer" },                            // 过期不发（如审批 10 分钟）
    "dedupeKey": { "type": "string" },                        // 幂等键：平台消息ID / ACP (sessionId,toolCallId,seq)
    "corr": { "type": "string", "description": "关联 ID：回复/审批对应的原请求" },
    "meta": { "type": "object", "additionalProperties": true } // 平台原始字段（_raw），仅调试
  },
  "$defs": {
    "endpointRef": { "type": "object", "required": ["family","adapterId"], "properties": {
      "family":    { "enum": ["agent","channel","scheduler","supervisor","system"] },
      "adapterId": { "type": "string", "description": "如 acp:claude、wechat-ilink" },
      "accountId": { "type": "string", "description": "多账号：哪个 Bot/哪个登录" },
      "peerId":    { "type": "string", "description": "对端用户/群 ID" },
      "deviceId":  { "type": "string" }
    }},
    "permissionPayload": { "type": "object", "properties": {
      "requestId": {"type":"string"},          // 对应 ACP JSON-RPC id
      "toolCallId":{"type":"string"},
      "title":     {"type":"string"},
      "risk":      {"enum":["low","medium","high"]},
      "options":   {"type":"array"},           // 原样保留 Agent 给的 optionId + kind
      "decision":  {"type":["string","null"]}  // 选中的 optionId
    }}
  }
}
```

### 2.1 ACP `session/update` → 信封 `kind` 映射

| ACP v1 `sessionUpdate` | 信封 kind | 默认是否外发到 IM |
|---|---|---|
| `agent_message_chunk` | `msg.delta`（Renderer 合并） | 合并后发 |
| `agent_thought_chunk` | `thought.delta` | 否（可配置） |
| `user_message_chunk` | `msg.text`（dir=in，回放时） | 否 |
| `tool_call` / `tool_call_update` | `tool.start` / `tool.update` / `tool.end` | 摘要发（可配置级别） |
| `plan` | `plan.update` | 是（卡片/列表） |
| `available_commands_update` | `session.info`（更新命令表） | 否 |
| `current_mode_update` / `config_option_update` | `session.info` | 否 |
| `session_info_update` | `session.info` | 否 |
| `usage_update` | `usage.update` | 否（汇总进日报） |
| `notice` | `notice` | 是 |
| `compaction_*` | `notice` | 否 |
| `session/request_permission`（请求） | `perm.request` | **是，p0** |
| `session/prompt` 响应 `stopReason` | `turn.end` | 以最终消息形式 |

v2 的 `state_update`、`*_message` upsert、`tool_call_content_chunk`、`plan_update` 在 `AcpV2Codec` 中映射到同一组 kind，Core 无感。

## 3. InputAdapter 接口（TypeScript）

```ts
export type InputFamily = "acp" | "stdio-custom" | "http-cloud" | "cli-oneshot";

export interface InputCapabilities {
  streamingText: boolean;      // 增量文本
  thoughts: boolean;
  toolEvents: boolean;
  plan: boolean;
  permissionRoundTrip: boolean;// 能把审批交给网关
  cancel: boolean;
  listSessions: boolean;
  resumeNoReplay: boolean;     // ACP sessionCapabilities.resume
  loadWithReplay: boolean;     // ACP loadSession
  fork: boolean;
  closeSession: boolean;
  localCodeAccess: boolean;    // Coze=false
  maxConcurrentSessions?: number; // 实测后填，未知=undefined
  slashCommands: string[];     // 来自 available_commands_update
  protocolVersion?: 1 | 2;
}

export interface AgentProfile {         // 后台配置的一条"输入端"
  id: string;                           // e.g. "claude@macbook:/repo/a"
  family: InputFamily;
  kind: "claude" | "codex" | "cursor" | "openclaw" | "zcode" | "coze" | string;
  launch?: { cmd: string; args: string[]; env?: Record<string,string>; cwd: string }; // 本机进程类
  http?: { baseUrl: string; botId?: string; tokenRef: string };                       // 云端类（密钥只存引用）
  permissionPolicy: "ask" | "auto-low-risk" | "deny-unattended";
  deviceId: string;
}

export interface InputAdapter {
  readonly profile: AgentProfile;
  start(): Promise<InputCapabilities>;                  // spawn + initialize(+authenticate)，返回协商能力
  stop(reason?: string): Promise<void>;

  newSession(opts: { cwd?: string; title?: string }): Promise<string>;           // → agentSessionId
  resumeSession(id: string, opts: { replay: boolean }): Promise<void>;           // v1: load/resume；v2: resume{replayFrom}
  listSessions?(cursor?: string): Promise<{ items: AgentSessionInfo[]; next?: string }>;
  closeSession?(id: string): Promise<void>;

  prompt(id: string, parts: ContentPart[], ctx: TurnContext): AsyncIterable<FleetEnvelope>; // 事件流（背压友好）
  cancel(id: string): Promise<void>;
  answerPermission(requestId: string, optionId: string | null): Promise<void>;  // null = 取消/超时

  health(): AdapterHealth;                               // 进程存活、最近错误、队列深度
}
```

### 3.1 四个协议族实现要点

| 实现 | 关键行为 | 来源事实 |
|---|---|---|
| `AcpInputAdapter` | 官方 TS SDK；stdout 首帧校验；按行缓冲（上限 32 MiB）；`initialize` 声明 `fs/terminal=false`；`authMethods` 非空则调用 `authenticate`（多数为"已预登录"）；Cursor 扩展方法：`cursor/ask_question`/`cursor/create_plan` 转成 `perm.request`（custom），超时回 `{outcome:"cancelled"}` | 01 §3–§7；Cursor ACP 文档 |
| `ZCodeAppServerAdapter`（experimental） | NDJSON **不带 jsonrpc 字段**；无握手；`session/create{workspace}` → `session/subscribe` → `session/send` → 消费 `session/event`；进程常驻（会话不可跨进程）；周期 `session/read` 对账 | 02 §5（社区逆向，部分确认） |
| `CozeHttpAdapter` | `POST /v3/chat` SSE；同 conversation 串行（防 4016）；`/clear` → `/v1/conversations/{id}/clear`；`requires_action` → `perm.request` 或工具回传 | 02 §6 |
| `CliOneshotAdapter`（降级/批处理） | Claude：`claude -p --output-format stream-json --verbose --resume <id>`；Codex：`codex exec --json` / `codex exec resume <id>`；Cursor：`agent -p --output-format stream-json --resume <chatId>`；ZCode：`zcode -p`；审批只能预授权（`--allowedTools`/`--sandbox`/`--force`），`permissionRoundTrip=false` | 02 §1–§5 |

### 3.2 进程池与并发（性能）
- **每个 AgentProfile 一个常驻进程**，同进程内多 session（ACP 规定一个连接可有多个会话）。
- **会话互斥**：`(profileId, agentSessionId)` 同时最多 1 个进行中 turn（Claude 同会话并发会交错写 transcript；Coze 同 conversation 并发报 4016）。其余输入排队，IM 侧回"已排队（第 N 位）"。
- **空闲回收**：会话 idle > N 分钟 → `session/close`（若支持）；进程 idle > M 分钟且无会话 → 优雅退出（SIGINT 优先于 SIGTERM，Claude 文档说明 SIGTERM 会丢本轮结果）。
- **背压**：`prompt()` 返回 AsyncIterable；Renderer 消费慢时在 Core 侧合并 `msg.delta`，不阻塞 Agent stdout 读取（读取线程只做解析与入环形缓冲）。
- 并发上限参数 `maxConcurrentSessions`：**待实测**（01/02 均为证据不足），默认每 Profile 4、全局 16。

## 4. OutputAdapter 接口

```ts
export interface ChannelCapabilities {
  receive: "longpoll" | "websocket" | "webhook";
  needsPublicUrl: boolean;
  dm: boolean; group: boolean; groupNeedsMention?: boolean;   // QQ 群需 @
  multiUserPerBot: boolean;          // 微信 ClawBot=false（1:1）
  proactive: "free" | "windowed" | "quota" | "none";          // 微信=windowed+quota；TG=free(须先/start)；QQ=quota
  proactiveWindowMs?: number;        // 微信 24h（部分确认）
  proactiveQuotaPerWindow?: number;  // 微信 ~10（部分确认）
  passiveReplyWindowMs?: number;     // QQ 单聊 60min / 群 5min
  formats: Array<"plain" | "markdown" | "html" | "card">;
  streamingEdit: "none" | "edit-message" | "card-stream";     // 飞书 CardKit / 钉钉 AI 卡片 / QQ 流式单聊
  buttons: boolean;                  // 有按钮 → 审批用按钮；否则用回复口令
  files: boolean; images: boolean;
  maxTextLen?: number;               // Discord 2000；其他待实测
  rate: RatePreset;                  // 见 §6
  broadcast: { supported: boolean; batchSize?: number; dailyCap?: number };
}

export interface ChannelAccount {     // 后台配置的一条"输出端账号"
  id: string;                         // e.g. "wechat:me", "feishu:corp-mgmt", "qq:lineB"
  adapter: "wechat-ilink" | "feishu" | "qq" | "dingtalk" | "discord" | "telegram" | string;
  credentialRef: string;              // 密钥引用（不落明文）
  ownerPeerId?: string;               // 微信：扫码者本人
  timezone: string;                   // 默认 Asia/Shanghai
}

export interface OutputAdapter {
  readonly account: ChannelAccount;
  connect(onInbound: (e: FleetEnvelope) => void): Promise<ChannelCapabilities>; // 建长连接/开始长轮询
  disconnect(): Promise<void>;

  send(e: FleetEnvelope, rendered: RenderedMessage): Promise<SendReceipt>;      // 只管投递；限流由 Outbox 负责
  update?(receipt: SendReceipt, rendered: RenderedMessage): Promise<void>;     // 编辑/卡片流式
  ackInteraction?(raw: unknown, toast?: string): Promise<void>;                // 飞书 3 秒内 ACK
  bindAccount?(): AsyncIterable<BindingEvent>;                                  // 扫码流程（微信/QR）
  health(): AdapterHealth;
}

export interface SendReceipt { platformMsgId?: string; accepted: boolean; retryAfterMs?: number;
  errorClass?: "rate_limited" | "window_expired" | "quota_exhausted" | "auth" | "forbidden" | "transient" | "fatal"; }
```

`errorClass` 归一化示例：Telegram 429 → `rate_limited`(retry_after)；飞书 230020/11233 → `rate_limited`，11247 → `quota_exhausted`；微信 `ret=-2` 且无新入站 → `window_expired`，`-14` → `auth`(暂停 1h)；钉钉 `too.many.people` → `rate_limited`；QQ 主动超频 → `quota_exhausted`。（错误码均见 03）

## 5. Router：四种模式 = 一张绑定表 + 策略

```ts
interface Binding {
  id: string;
  mode: "management" | "notification" | "team" | "supervisor";
  inputs: string[];          // AgentProfile.id 或标签选择器 tag:productA
  outputs: string[];         // ChannelAccount.id[:peer]
  direction: "both" | "in-only" | "out-only";
  filter?: { kinds?: string[]; minPrio?: "p0"|"p1"|"p2"|"p3" };
  replyTarget: "last-active" | "pinned";   // IM 回复时送往哪个 Agent
  fallbackOutputs?: string[];              // 主渠道不可达（如微信窗口过期）时的降级
}
```

| 模式 | 输入:输出 | 绑定写法 | 回复路由 |
|---|---|---|---|
| 管理（多→1） | 6 Agent → 1 微信 | `inputs: ["tag:all"], outputs: ["wechat:me"]` | 默认"最后活跃会话"；`/use codex` 显式切换；消息前缀 `[Codex·repoA]` 标识来源 |
| 通知（1→多） | 1 资讯 Agent/定时任务 → N 用户 | `direction:"out-only"`，outputs 为订阅组 `sub:ai-daily` | 用户回复进入各自独立会话（每订阅者一个 fleetSession） |
| 团队（多→多） | 产品线 A → 微信；B → QQ；公司 → 飞书 | 多条 Binding 并存，按 tag 路由 | 每个渠道回复只路由到其绑定内的 Agent |
| 总控 | N Agent ⇄ Supervisor ⇄ 输出端 | `inputs` 的出站先送 `supervisor`，由其决定直接回复、转交、或上报 | 用户随时与总控对话（独立会话，不打断执行中的 turn） |

**总控模式落点**：Supervisor 本身实现为一个特殊 InputAdapter（`family:"supervisor"`，模型可配、skill 可配），它订阅其他 Agent 的 `turn.end/perm.request/error`，可调用 Core 的 `dispatch(agentId, prompt)`。"开会"= Supervisor 依次/并行向多个 Agent 发同一需求、收集回答、汇总——**协议层不存在 Agent 互通，全部由网关编排**（01 §2）。

## 6. 出站流水线：Renderer → Outbox → RateLimiter → Adapter

1. **Renderer（降级链）**：`card → markdown → plain`；按 `maxTextLen` 切分；`diff` 在不支持文件的渠道折叠为摘要 + "回复 /diff N 查看"；`msg.delta` 合并策略：
   - `streamingEdit=card-stream`（飞书/钉钉）：创建卡片后每 300–800 ms 推一次增量；
   - `edit-message`：节流编辑；
   - `none`（微信）：**只发最终消息**（turn.end），中途仅在超过 60 s 时发一次"进行中"——直接受微信 ~10 条额度约束。
2. **Outbox**：SQLite 表，`status: queued|sending|sent|failed|expired`；至少一次投递 + `dedupeKey` 幂等；`ttlMs` 过期即丢弃并记录。
3. **RateLimiter（多级令牌桶）**：`global(adapter)` → `account` → `peer/chat`；预设：

| 渠道 | 预设（来源 03） |
|---|---|
| 飞书 | 账号 50/s & 1000/min；单用户 5/s；单群 5/s；批量日上限 50 万 |
| Telegram | 全局 30/s（付费可 1000/s）；单聊 1/s；单群 20/min |
| QQ | 单聊 Bot 10/s（未认证 5/s & 30/min）、单关系 20/min、1000/天；群 60/min、单群 20/min、1000/天 |
| 钉钉 | batchSend 每批 20 人；自定义群 20/min（超限冷却 10 min） |
| Discord | 全局 50/s，读响应头动态调整 |
| 微信 ClawBot | 不按 QPS，按 **(bot,user) 窗口额度**：入站重置为 Q（默认 10，可配），窗口 24h；剩 ≤3 时附"回复任意字续期"提示；耗尽 → fallbackOutputs 或排队至下次入站 |

4. **优先级**：p0（审批/告警）可抢占额度；p3（资讯）在额度紧张时合并成摘要。

## 7. 审批（PermissionBroker）

```
Agent ──session/request_permission(id=42, options=[{optionId:"allow-once",kind:"allow_once"},...])──▶ Core
Core: perm.request(p0, ttl=10min) ─▶ Router ─▶ 输出端
   ├ 有按钮(飞书/钉钉/Discord/TG/QQ键盘)：渲染按钮，回调里带 requestId+optionId；飞书须 3 s 内 ackInteraction
   └ 无按钮(微信)：渲染 "回复 Y1 允许一次 / Y2 总是允许 / N 拒绝"，replyToken 绑定 requestId
用户操作 ─▶ inbound perm.decision ─▶ 校验(发起者是否有权、是否过期、是否已决) ─▶ answerPermission(42, optionId)
超时 ─▶ 按 Profile.permissionPolicy：ask→回复 cancelled；auto-low-risk→仅低风险自动允许；deny-unattended→拒绝
```
- 永远按 `kind` 理解语义、按 `optionId` 回复（Cursor 的 optionId 字面量与 kind 不同，01 §5）。
- "总是允许"只写入网关策略表时需二次确认（防误触）。

## 13. 5W1H

- **What**：一套信封 + 两类适配器接口 + 路由/命令/审批/限流四个核心服务，覆盖 6×6 端点与 4 种模式。
- **Why**：把"每个工具独占一个 IM 绑定"变为"网关独占、多路复用"；把各家异构协议收敛为一个内部事件模型，新增端点成本降为"写一个 Adapter 或一条配置"。
- **Where/When**：Edge 在设备上常驻；Hub 仅在需要公网回调/大规模广播/多设备时启用；会话恢复发生在 Agent 进程启动后、首个 prompt 前。
- **Who**：Core 团队维护信封与 Router；每个 Adapter 有独立 owner 与契约测试；用户在后台配置 Binding；总控模型由用户自选。
- **How**：TS/Node（官方 ACP TS SDK）实现 Edge；SQLite WAL；令牌桶 + Outbox；插件清单。
- **What if**：
  - 配置缺失（无输出端）→ 事件只落库，Admin UI 告警。
  - 依赖服务不可用（微信长轮询失败）→ 指数退避；p0 走 fallbackOutputs。
  - 接口字段变化（ACP v2 / iLink 字段）→ 只改 Codec，信封不变。
  - 端口被占用 → 启动失败并报错（§11）。
  - 输出端额度耗尽 → 合并摘要、排队、降级。
  - 测试通过但运行时失败（如飞书集群模式导致多实例只一个收到）→ Edge 单实例；Hub 多实例时状态外置。
  - 原始前提不成立（例如腾讯开放多用户 ClawBot）→ 改能力位即可，Router 自动允许微信承担通知模式。

## 14. 苏格拉底追问 & 双向钢人

**主张：统一信封 + 能力位能覆盖所有端点。**
- 凭什么？01–03 已列出所有端点的事件形态，均可映射到 §2 的 kind 集合；不能映射的放 `meta`。
- 反方最强论点：①"最小公分母"会丢失平台特性（飞书审批流、QQ 键盘、Cursor create_plan）；②流式合并策略在不同渠道体验差异巨大；③单 SQLite 在高并发广播时成为瓶颈。
- 回应：①`card` part + `cardRef` 允许平台专属渲染器，信封不限制上限；②合并策略已按 `streamingEdit` 分支；③广播放 Hub，Hub 可换 Postgres + 队列（如 NATS/Redis Streams，`证据不足`：未做压测选型）。
- 仍成立的反对意见：总控模式的"开会"质量取决于摘要质量，非协议问题，需后续专项研究。

**主张：微信用"只发最终结果"策略。**
- 反方：长任务用户会以为卡死。→ 折中：>60 s 发一次进度（消耗 1 条额度），并在 `/status` 查询时由用户入站触发（入站本身续期额度，免费）。

## 15. 最终判断

- **结论**：采用 §2 信封、§3/§4 接口、§5 绑定表实现四模式；Edge 优先、Hub 可选。
- **依据**：01–03 的官方事实（ACP 方法与能力位、各渠道收发机制与限额）。
- **前提**：微信 1:1/24h/~10 条约束按 `部分确认` 处理为可配置参数；各 Agent 已在设备登录。
- **局限 / 未验证**：并发上限、进程内存、飞书卡片回调是否可走长连接、微信斜杠文本送达、QQ 主动配额真实值——均需实测；端口 3000/3333 语义待确认。
- **风险**：平台政策变更（尤其微信）；ACP v2 迁移；ZCode 私有协议。
- **下一步**：①按 §10 契约测试先做 `acp:claude`、`acp:codex`、`wechat-ilink`、`feishu` 四个 Adapter 的 PoC；②实测并回填 capability 表；③确认端口语义。
- **是否允许进入下一阶段（PoC 开发）**：**允许**，但 PoC 结束前不得把任何 `证据不足` 项写成默认开启。
