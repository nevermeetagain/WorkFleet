## 0. 一页速览（★ 项）

| 编号 | 问题 | 推荐默认（一句话） |
|---|---|---|
| A-01 ★ | “ACP 工具”指什么 | ACP = Agent Client Protocol；本产品 = 输入侧 ACP Client + 输出侧 IM 通道的**路由网关**，IM 侧不是 ACP |
| A-02 ★ | 管理模式里“也需要支持发送”怎么发 | 回复默认发给“当前回复目标”；`@别名` 指定；`/use` 切换；**绝不默认广播** |
| A-03 ★ | 通知模式“接收不同用户的消息”是什么 | 订阅者可发命令与提问；每人一个隔离会话；管理员可选看汇总 |
| A-05 ★ | “总控模型必须运行在设备上” | 总控**进程与状态**在本机；推理可调用云 API，也可选本地模型 |
| A-06 ★ | “其他模式大概率是两端直连” | 理解为“不经 LLM 中转的透传”，网关仍在本机常驻中转 |

## 9. 四轮收口（针对“哪些是真歧义”）

- **5W1H**：What——45 条歧义（A-01~A-46，A-26 编号预留未用），12 条 ★；Why——原文是需求口述稿，含笔误（A-13）、模板残留（A-09、A-44）、未定义术语（A-07、A-16）；Where/When——集中在模式语义、总控、场景 4；Who——基本都需用户定，A-41 由研究方提议；How——每条给推荐默认，使研究不阻塞；What if——若用户对 A-02/A-06/A-11 的回答与推荐相反，核心路由设计需要返工。
- **苏格拉底追问**：“A-09 真的不矛盾吗？”——证据为 ADR-005 端口段与原文端口号的数值关系（3000∈[3000,3100)，3333∈[3300,3400)），来自最新代码 `docs/架构.md`；相反可能：端口表被后续修改或另有口径 → 结论成立的前提是 ADR-005 仍是唯一权威。“A-21 ZCode 身份”——仅搜索摘录，未打开仓库源码 → 部分确认。
- **双向钢人**：支持——每条有原文引用、选项与影响，推荐默认均有证据或 V0.0.1 设计支撑。反对——推荐默认可能带有研究方偏好（如偏向同仓 C2）；部分“歧义”用户可能认为不言自明。处置——推荐默认显式标注可推翻；★ 只标会改变架构/范围的项，降低用户回复负担。
- **最终判断**：清单可用于驱动用户确认；**允许**按推荐默认继续后续研究；**暂不执行**任何依赖 ★ 项的范围裁剪与汇总表权重定稿。
