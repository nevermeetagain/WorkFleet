### 3.2 加权得分
`得分 = Σ(维度分/5 × 权重)`，范围 0–100。D01 另报**原始覆盖率**（P0、P1 分别计），不得只报加权分。

### 3.3 一票否决与封顶规则（先于加权执行）

| 规则 | 条件 | 处理 |
|---|---|---|
| G1 许可证 | D17 ≤1（GPL/AGPL/无许可/EULA/禁止商用）且 A-45 选闭源 | D08 封顶 1（仅设计借鉴）；档 A 不得作为 fork 底座 |
| G2 设备端 | D23 = 0（无法单机运行） | 不得作为档 A 底座（总控必须运行在设备上，R-602） |
| G3 活跃度 | D18 = 0（>12 个月无提交） | 档 A 不得入选；档 B 仅可借鉴设计 |
| G4 证据 | 该维度无 E4/E5 证据 | 该维度封顶 3 分 |
| G5 安全 | D16 = 0 且需直接复用其代码 | 复用前必须列出安全修复项并计入工作量 |
| G6 P0 覆盖 | 档 A 候选缺任一 P0 需求且无可行补充方案 | 标“不满足大部分需求”，无论加权分多少 |

### 3.4 “满足大部分需求”的判定
- 主口径：档 A 加权 ≥80 且通过 G1–G6（沿用 V0.0.1 “统一加权 ≥80%” 阈值，`40-综合/00 §1`）。
- 辅口径：P0 需求覆盖 100% 且 P0+P1 覆盖 ≥60%（A-41，待用户确认）。两口径结论不一致时两者都报告。

### 3.5 敏感性检查（必做）
1. 等权重重算（26 维各 100/26）；2. 对档 A 前 5 大权重各 ±30% 扰动；3. 若候选排名第 1 名发生变化，结论降级为“部分确认”并说明是哪一维驱动。脚本与输入 CSV 存放在 `50-附录/评分底稿/`。

|---|---|---|---|
| E5 | 本轮实测：命令 + 原始输出（或日志文件） | `python -m pytest tests -q` 输出；真机收发记录 | 已确认 |
| E3 | 官方文档/规范原文（带 URL 与访问日期） | open.feishu.cn 限额页 | 已确认（文档层面）/ 有冲突时部分确认 |
| E2 | 官方 issue、维护者回复、release note | `Tencent/openclaw-weixin` issue #202 | 部分确认 |
| E1 | 社区文章、第三方实测、搜索摘录 | 博客、搜索结果摘录 | 部分确认（需交叉印证）/ 证据不足 |
| E0 | 推理或经验判断 | “应该支持” | 证据不足 / 待确认 |

### 4.2 规则
1. **最新代码**：每个仓库在分析当天执行 `git clone --depth 1` 或 `git fetch` + `git rev-parse HEAD`，在报告头部记录 `仓库 / 分支 / SHA / 提交日期 / 拉取时间（UTC）`；V0.0.1 的 SHA 只能作为对照，不可直接沿用。
2. **行号绑定 SHA**：所有 `文件:行` 引用必须属于报告头部声明的 SHA。
3. **搜索摘录不是证据**：web 搜索的摘录只能作为线索（E1）；要作为 E3 必须 `web_fetch` 打开原页。
4. **冲突必须并列**：同一事实有冲突来源（如 QQ 主动配额“每月 4 条” vs “每天 1000 条”，`30/03 §3`）时，两者都写出，标“部分确认”，并给出以哪个为准的理由。
5. **未运行不得称“通过”**：未执行的测试只能写“文档声明 N passed（未复现）”。
6. **推断显式标注**：E0 结论必须写“推断：……，依据：……”。
7. **数字带口径**：匹配度、工作量、性能数字必须注明计算口径与输入（指向底稿 CSV）。
8. **许可证以 LICENSE 文件为准**：README 徽章与 LICENSE 不一致时以 LICENSE 为准，并记录不一致。
9. **时间**：所有时间注明时区；GitHub/浏览器时间默认 UTC 或美东，转换为 Asia/Shanghai 再写结论。
